# EasyEDA Pro 자동 설계 파이프라인 개발 규칙 (Workspace Rules)

이 프로젝트(`majn/인증준비/mcp_development`)에서 EasyEDA Pro와 파이썬 자동 설계 파이프라인을 이어서 개발하거나 개선할 때, 모든 AI 에이전트가 엄격하게 준수해야 할 개발 지침 및 행동 규칙입니다.

---

## 1. EasyEDA 에디터 및 브릿지 서버 제어 규칙
* **연동 구조 인지**: EasyEDA Pro 에디터(플러그인 `run-api-gateway` 장착)와 로컬 파이썬 클라이언트는 Node.js Bridge Server(포트 `49620`)를 통해 통신합니다.
* **서버 상태 검증**: EasyEDA API를 호출하기 전에 반드시 `http://localhost:49620/health`를 체크하여 브릿지 서버와 에디터 연결이 활성화되어 있는지 선제 확인해야 합니다.
* **JS 코드 실행**: 에디터 조작은 `easyeda_mcp_client.py`의 `execute_js()`를 통해 에디터 내부 JS 엔진으로 코드를 송신하여 수행합니다.

## 2. 설계 및 부품 배치 규칙
* **LCSC 라이브러리 캐시 갱신**: `place_component` API를 실행해 부품 배치 시 에러가 발생하는 경우, EasyEDA Pro 에디터 상에서 해당 LCSC ID 부품을 직접 검색(`Shift+F`)하여 에디터 로컬 캐시를 활성화하도록 사용자에게 명확히 안내해야 합니다.
* **동박(Copper Pour) 재구축 지침**: 배선 완료 또는 구조 변경 후 동박이 채워지지 않았거나 불완전해 보이는 현상이 있다면, 반드시 에디터 창에서 **`Shift + B`** 단축키를 눌러 동박을 강제 재구축(Rebuild)하도록 가이드하십시오.
* **저장 단축키 안내**: 에디터 API를 통한 자동 저장은 비정상 동작이 빈번하므로, 주요 변경 작업 완료 후 사용자에게 **`Cmd + S` / `Ctrl + S`**로 저장할 것을 상시 안내하십시오.

## 3. 검증(DRC) 및 내보내기 규칙
* **자가 검증 파이프라인**: 설계 변경이 발생하면 항상 `run_full_drc.py`를 실행하여 핀/트랙 클리어런스, 트랙 교차(Crossings), 그리고 에디터 내장 DRC 연동 결과를 확인하십시오.
* **거버 파일 출력**: 최종 PCB 사양이 완벽히 검증되면 `run_export_gerber.py` 스크립트를 구동하여 `Gerber_Output.zip` 파일을 루트 폴더에 정상 생성해 제공해야 합니다.
