## 2. 단계별 실행 계획

각 단계는 **완료 기준을 통과해야 다음 단계 진행**. 단계마다 코드 diff·빌드 결과·미해결 사항을 `AGENT_SHARED_LOG.md`에 기록하고 커밋한다.

### R1. Wi-Fi 접근 제어 복구 (F1·F2·F3)
**설계 결정**
1. SoftAP는 **WPA2-PSK 필수**. 비밀번호는 소스에 고정하지 않는다.
   - 최초 부팅 시 `esp_random()`으로 10자 영숫자 생성 → NVS(`Preferences`, 네임스페이스 `majn`) 저장 → 이후 재사용.
   - 최초 생성 시 시리얼(TX)에 1회 출력 + 기기 라벨 기록용으로 사용자에게 전달. (오픈 AP로 되돌아가는 경로 없음)
   - 분실 복구: 버튼이 없으므로 BLE(R2 인증 통과 후) 명령 `RESET_WIFI_CRED`로 재생성 → 재부팅.
2. 웹 세션 토큰은 부팅마다 재생성(현행 유지). 노출 경로 정리:
   - `/api/status` JSON에서 `auth_token` **삭제**.
   - 토큰은 `/` 응답 HTML에 인라인 주입(WPA2 인증된 클라이언트만 도달) + `HttpOnly; SameSite=Strict` 쿠키.
   - `/api/status`·`/api/command`·`/update` 모두 인증 필수. 무인증 허용은 `/api/ping`(`{"status":"ok"}`)과 캡티브 포털 경로뿐.
3. CORS `Access-Control-Allow-Origin: *` 제거 → 동일 출처만(헤더 미설정). OPTIONS 핸들러는 유지하되 와일드카드 금지.
4. `/update` 폼의 토큰 자동 채움은 유지(WPA2 내부이므로 허용).

**수정 파일**: `wifi_manager.cpp/.h`, `main.cpp`, `mobile_web_ui.h`
**완료 기준**
- [ ] 빌드 0 error / 0 warning
- [ ] 소스 grep: 고정 비밀번호·고정 토큰·`auth_token` 응답 필드 0건
- [ ] 호스트 스크립트(`tools/`)로 에뮬/모의 응답 점검은 불가하므로 **정적 검토 체크리스트**(엔드포인트별 인증 요구 표) 문서화
- [ ] 실기 검증은 R6 이후(보류) — 단계 결과에 "미검증" 명기

### R2. BLE 접근 제어 (F4)
**설계 결정**
1. `BLEDevice::setEncryptionLevel(ESP_BLE_SEC_ENCRYPT_MITM)` + Passkey Entry(6자리). PIN은 NVS 저장, 최초 생성 시 시리얼 출력.
2. Command / Telemetry / Event / OTA 특성에 **암호화 필요 권한**(`ESP_GATT_PERM_READ_ENC_MITM`, `WRITE_ENC_MITM`) 부여.
3. 미페어링 상태에서 광고·이름 노출은 허용하되 모든 특성 접근은 거부.
4. 페어링 정보는 본딩(NVS)으로 유지 → 재연결 시 재입력 불필요.
5. 메모리: Bluedroid 보안 스택 추가로 힙 감소 → R5에서 `min_free_heap` 실측.

**수정 파일**: `ble_manager.cpp`, `ota_ble_service.cpp`
**완료 기준**
- [ ] 빌드 0/0, IRAM 잔여 ≥ 4 KB (현재 9.7 KB) — 미달 시 NimBLE 전환 검토를 별도 안건으로 보고
- [ ] 코드상 모든 특성 권한이 ENC_MITM임을 diff로 증빙
- [ ] 실기(nRF Connect/Web Bluetooth) 페어링 시험은 R6 이후

### R3. RF 출력 정책 (F5)
1. 기본값 **15 dBm(이전 값)** 복귀. 컴파일 플래그 `MAJN_WIFI_TX_DBM`(기본 15)으로 분리, 19.5는 시험 환경(`esp32_wifi_phone_txtest`)에서만.
2. 안테나 상태별 시험 계획 (실기, 맥북 Wi-Fi 미변경 — 폰에서만 관찰):
   | 조건 | 출력 | 관찰 |
   |------|------|------|
   | u.FL 개방 | 15 / 19.5 | iPhone 검색 가능 최대 거리(cm), 연결 유지 여부 |
   | 3.1 cm 간이선(λ/4) | 15 | 거리·RSSI |
   | 정식 u.FL 안테나(≤2.33 dBi, KC 승계 조건) | 15 | 거리·RSSI |
3. 전류 실측(전원 입력단 전류계)으로 AP2112K 여유 확인: Wi-Fi 대기 / HTTP 부하 / +BLE / +12 V 부스트·앰프. 3.3 V 레일 최저 > 3.0 V, 브라운아웃 0회가 통과 기준.
4. **권고(비용 2~3천 원)**: 정식 u.FL 안테나 구매·체결이 근본 해결. 출력 상향은 임시방편으로 문서화. 규제 적합성은 "KR 도메인 설정"까지만 주장.

**완료 기준**: 코드 분리 완료(R3-코드), 실측 표는 R6 이후 채움. 미실측 상태에서 19.5를 기본값으로 쓰지 않는다.

### R4. 롤백 정책·상태 표시 정비 (F6·F7)
1. **롤백 게이트 재정의** (펌웨어 결함 vs 하드웨어 결함 분리):
   - 롤백 대상(펌웨어 결함): 태스크 핸들 NULL, 힙 < 30 KB, Wi-Fi/BLE 초기화 실패, 부팅 직후 안전 락 발동.
   - 롤백 비대상(하드웨어 결함): 앰프 초기화 실패 → **VALID 확정 + FAULT 잠금(진동 불가) + 무선 유지**. 무선 OTA가 유일한 복구 경로이므로 보존. 상태/로그에 `AMP_FAULT` 명시.
2. 상태 모델에 `STOPPING` 추가: `!systemActive && currentAmp > 0.001` 구간. STOP/타이머/하트비트 정지 시 ACK 상태 `STOPPING`, 감쇄 종료 후 `READY`. 웹 UI·BLE 텔레메트리에 반영.
3. 롤백 관련 ESP-IDF 반환값은 전부 로그(현행 유지).

**수정 파일**: `main.cpp`, `system_controller.cpp`, `safety_manager.cpp`, `mobile_web_ui.h`, `ble_manager.cpp`
**완료 기준**: 빌드 0/0 + 상태 전이표(문서) + 롤백 판정표(문서)

### R5. 정적·구조 검증 강화 (코드 레벨에서 가능한 최대치)
1. 빌드 플래그 `-Wall -Wextra` 활성화 환경에서 경고 0 확인(기존 라이브러리 경고는 분리 기록).
2. `handleJsonCommand` 입력 퍼징: 호스트에서 ArduinoJson 파싱·범위 검증 로직만 분리해 단위 테스트(비정상 JSON, 범위 초과, 거대 payload, 중복 명령). `tools/test_command_parser.py` 또는 PlatformIO native 테스트.
3. 동시성 검토 체크리스트: `systemActive`·`activeStateStartTime` 접근 지점 전수 표(코어/ISR/태스크), 뮤텍스 보호 범위, 타임아웃 시 동작.
4. 힙·스택: `uxTaskGetStackHighWaterMark`를 `/api/status`(인증됨)에 추가해 R6 실측 준비.
5. 요구사항 추적표: 마스터플랜 W1~W7 항목 ↔ 코드 위치 ↔ 검증 방법 ↔ 상태(코드완료/실기미검증).

**완료 기준**: 테스트 통과 로그 저장(`logs/firmware/`), 추적표 커밋.

### R6. 실물 검증 게이트 (사용자 승인 필요 — 현재 HOLD)
**선행 확인 (F8)**
1. 현재 보드의 부팅 로그(시리얼 TX 로그 읽기 전용)에서 펌웨어 버전·파티션 테이블·롤백 활성 여부 확인. **파티션 구성이 새 이미지(app0 0x10000 / app1 0x340000, otadata 0xe000)와 다르면 OTA 불가** → 이 경우 계획 중단하고 사용자와 대안 협의.
2. 현재 탑재 펌웨어에 OTA 엔드포인트가 있는지, 있다면 인증 방식 확인.
3. 새 이미지 크기(≈1.9 MB) < 슬롯(3.19 MB) 확인.

**승인 요청 시 제시물**: 바이너리 SHA-256, 직전 정상 복구 경로(롤백 슬롯 유무), 중단 시 대응.

**승인 후 순서** (한 번에 한 항목, 각 항목 통과 후 진행)
1. Wi-Fi OTA 1회(vibration idle 상태) → 재부팅 → 시리얼 로그에서 `PENDING_VERIFY → VALID` 확인
2. WPA2 AP 검색·연결(iPhone, Android 각 반복 10회), DHCP, 웹 접속
3. 인증 시험: 토큰 없는 `/api/command`·`/update` → 401, 다른 기기 비인증 BLE 쓰기 → 거부
4. 웹 제어: START/STOP/ESTOP/타이머 만료 소프트 스톱 (더미 부하, 영아 없음)
5. BLE 페어링·명령·텔레메트리·끊김 시 안전 정지
6. Wi-Fi+BLE 동시(10분): 상호 명령, 5 s 하트비트, 힙 추세
7. 재접속 시험(AP 재부팅, 폰 Wi-Fi 토글, 화면 잠금, BLE 재연결, 반복 20회) + 힙 누수 확인
8. OTA 실패 시험: 비-ESP32 파일, 전송 중단, 잘못된 토큰 → 기존 펌웨어 유지
9. 롤백 시험은 **별도 벤치용 이미지**(의도적 초기화 실패)로 수행. 운영 이미지에서는 하지 않는다.

**통과 기준**: 각 항목 로그·사진·수치를 `logs/firmware/` 및 `data/measurements/`에 저장. 실측 근거 없는 "통과" 표기 금지.

### R7. 동결 조건
R1~R6 전 항목 통과 + iPhone·Android 각각 Wi-Fi/BLE/제어/복구/OTA 검증 기록이 있을 때만 W7(버전 동결) 선언. 그 전에는 상태를 "코드 완료·실기 미검증"으로만 표기.

## 3. 일정/의존 관계

```
R1 ─┬─> R2 ─┐
    └─> R3 ─┼─> R4 ─> R5 ─> [사용자 승인] ─> R6 ─> R7
```
R1~R5는 실물 없이 진행 가능(코드·빌드·정적 검증). R6만 보드·사용자 입회·승인 필요.

## 4. 결정 사항 (기본값으로 진행, 이견 시 변경)

| 항목 | 기본 결정 |
|------|-----------|
| AP 보안 | WPA2-PSK, 기기별 랜덤 비밀번호(NVS), 시리얼 1회 출력 |
| BLE 보안 | Passkey(MITM) + 본딩 |
| TX 출력 | 기본 15 dBm, 19.5는 시험 빌드 전용 |
| 앰프 고장 시 | 롤백 안 함, FAULT 잠금 + 무선 유지 |
| 안테나 | 정식 u.FL 안테나(≤2.33 dBi) 구매 권고 |

## 5. 리스크

- BLE 보안 스택으로 IRAM/힙이 더 줄 수 있음 → R2 완료 기준에 잔여 IRAM ≥ 4 KB 명시, 미달 시 NimBLE 전환을 별도 안건으로 보고.
- 비밀번호 분실 시 Wi-Fi 접속 불가 → BLE 복구 경로로 완화, BLE도 막히면 시리얼 로그(TX)로 확인.
- 현재 보드 펌웨어/파티션 불명 → R6 선행 확인에서 막히면 OTA 불가 가능성 존재(서면 보고 후 협의).
