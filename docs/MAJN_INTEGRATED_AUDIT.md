## 1. 현재 상태 요약

- 최신 기록된 하드웨어 타깃 빌드: `esp32_full_hw` 성공, 0 errors. 기록상 Flash 1,807,199 bytes, RAM 69,272 bytes, `.bin` 1,807,600 bytes, SHA-256 `55287307964ccf5bf6fa8ff509e7b1038a0414a0c5f267ae599b56c4892acd29`. 원시 로그 경로는 `logs/firmware/2026-10-25_esp32_full_hw_boot_and_p0_fixes_build.log`로 기록되어 있다. 이 감사에서는 실제 바이너리를 내려받아 해시를 독립 재계산하지 않았다.
- 기록상 deprecation 경고 2건(legacy ADC/I²S)이 있다. “0 errors”는 가능하지만 “0 warnings”로 기술하면 안 된다.
- PCB #0005에서 BLE 연결 및 START/RUNNING 표시가 관찰됐으나, 익사이터 출력 실패가 보고되어 있다. 현재 소스의 빌드 성공과 실제 익사이터 구동은 별개다.
- 실물 보드 플래시/OTA, 실제 Flash 용량, 전원 레일 및 차단 시간, 더미 부하 출력·발열, 패드 상면 3축 가속도는 미검증이다.
- 영아 대상 시험, 임상 효능, 영아 안전성, KC/EMC 적합성은 입증되지 않았다.
- 회로도·PCB의 정본은 EasyEDA Pro 클라우드로 기록되어 있고 Git SSOT v1.9.2만으로 최신 배선/풋프린트 일치 여부를 확정할 수 없다.

| IA-021 | **30분 제한을 ‘KC 기준’이라고 표현.** `main.cpp` 주석에 “KC infant safety standard: 30 minutes”가 있으나 정확한 제품 분류·규격·조항이 현재 기록에 없다. | 규정상 의무와 내부 정책이 혼재될 수 있다. | 공식 적용 규격과 조항을 확인하기 전 주석을 “내부 자동정지 정책(임시)”로 바꾸고, 법규 주장에는 검증 가능한 출처를 연결한다. |

## 3. 설계·제품·증거 영역 감사

### 하드웨어 설계
- Git의 `mcp_design_flow.json`은 설계 기준 파일이지만 실제 배치·배선은 EasyEDA Pro 클라우드에 있다고 README가 명시한다. 현재 원격 파일만으로 최신 PCB와 SSOT의 동기화를 보장할 수 없다.
- L1/D3 부품 표기와 MP3426 승압 루프, TAS5805M 전원/디커플링/BTL 출력 경로는 최신 회로도·PCB 내보내기와 데이터시트 대조가 필요하다.
- 현재 PCB #0005에서 익사이터가 반응하지 않았다는 보고는 출력 체인 bring-up이 완료되지 않았다는 뜻이다. BLE RUNNING ACK는 앰프 출력/패드 진동의 증거가 아니다.
- 우선 계측은 익사이터 분리 상태의 전류 제한 전원, 레일 전압, PDN/BOOST_EN 상태 확인이다. BTL 출력은 접지 기준 단자 전압만으로 판정하지 말고 적절한 차동 측정 장비/절차를 사용한다.

### 제품 안전·임상·규제
- 현재 자료는 문헌·계획·소스 코드·시험 프로토콜이며, MAJN 자체의 영아 진정 효능이나 안전성을 입증한 임상/실측 데이터가 아니다.
- 제품의 적용 규제 분류와 KC/EMC 요구사항은 제품 구조·사용 목적·판매 형태에 맞춰 공식 기관/시험소와 확인해야 한다. 주석이나 내부 기준을 규정 근거로 대체하지 않는다.
- 영아 대상 시험은 전문기관의 윤리·안전 검토 및 사전 비임상/기구·전기 검증 이후에만 논의한다. 현재 단계에서는 성인 감독 하의 비생체 더미 부하/패드 계측에 한정한다.
- 진동 주파수·진폭 소프트웨어 값은 가속도(m/s² 또는 g), 변위, 전달함수, 매트리스/하중별 편차를 대체하지 않는다.

### BLE UI·프로토콜
- 상태/ACK의 “applied”는 실제 하드웨어 적용 완료와 분리한다. 특히 STOP, OTA_BEGIN, REBOOT, SET_PRESET은 실제 효과 확인이 필요하다.
- UI에서 가상 센서·미측정 값·추정값을 실제 계측치로 표시하지 않는다. 목표값, 명령 상태, 보드 IMU, 패드 상면 실측을 별도 필드로 구분한다.

## 4. 일괄 수정 순서와 의존성

1. **물리 Flash 용량 확인 및 파티션 정합화 (IA-001).** 확인 전 OTA를 하지 않는다.
2. **상태·동시성 안전 기반:** I²C 직렬화(IA-004), ISR-safe 차단(IA-003), ESTOP 복구(IA-002), fail-closed 부팅/START(IA-005~009).
3. **정지·전력 상태 보장:** 정상 램프와 ESTOP 분리(IA-010), STOP/REBOOT/OTA 진입 인터록(IA-012~015), IMU 인터럽트(IA-011).
4. **OTA 보안·세션:** 인증/서명 검증(IA-016), 파티션 기반 크기(IA-017), abort/cleanup 및 오류 상태(IA-014, IA-030).
5. **기능 정합성:** preset, 진단 레지스터, 범위 검증, 텔레메트리/폐루프 표현(IA-018~025).
6. **하드웨어 설계·검증 기준 정합화:** 최신 EasyEDA 내보내기 비교, 전원/출력/열 시험 계획, 근거 있는 규격·시험 한계(IA-026~027).
7. **전체 재검토:** 변경 전체 diff를 독립 재검토하고 빌드/정적 시험/물리 시험 상태를 각각 갱신한다. 발견 항목을 다시 쪼개서 즉시 수정하지 말고, 새 발견은 이 통합 목록에 추가한 뒤 우선순위와 의존성을 다시 정리한다.

## 5. 종료 기준

### 코드·설정 종료
- P0/P1 모든 항목에 수정 커밋 또는 “수정하지 않는 이유”가 연결됨.
- clean `esp32_full_hw` 빌드 성공, 경고 포함 전체 로그 저장, 바이너리 해시와 소스 커밋 대응 확인.
- 입력 범위, 태스크 생성 실패, I²S/IMU/앰프 초기화 실패, ESTOP/RESET_FAULT, STOP→START, OTA 중단·오류에 대한 자동화 또는 재현 가능한 시험 기록이 있음.
- 코드가 표시하는 상태/ACK가 실제 수행 결과와 일치함.

### 실물 검증 종료
- PCB 리비전과 실제 Flash 용량 확인.
- 전원 레일/대기 전류, PDN/BOOST_EN, fault 차단시간, 더미 부하 차동 출력·발열을 적절한 장비로 계측.
- 조립된 기구에서 패드 상면 3축 가속도 원시 데이터(센서·위치·방향·샘플링·하중·매트리스 조건 포함)를 저장.
- 모든 결과는 소스 SHA, 바이너리 SHA-256, PCB 번호, 장비, 조건, 원시 파일 SHA-256과 연결됨.

### 제품 주장 종료
- 임상 효능·영아 안전성·규제 적합성은 위 코드/벤치 시험만으로 완료 처리하지 않는다. 각각 적절한 연구 설계, 전문기관/시험소의 판단 및 실제 증거가 별도로 필요하다.

## 6. 확인하지 못한 것 / 감사 한계

- 실제 PCB #0005, 전원 레일, Flash JEDEC ID, 익사이터/패드 상면 파형은 직접 계측하지 않았다.
- 최신 EasyEDA Pro Schematic1/PCB1 내보내기, 최신 BOM, 제조 DRC 결과는 이 감사 시점에 대조하지 않았다.
- Secure Boot/eFuse/이미지 서명/실제 BLE bonding 설정은 빌드·보드 설정을 완전 확인하지 못했으므로 “미확인”이다.
- 이 문서는 독립적인 규제/임상 검토나 인증서가 아니다.
