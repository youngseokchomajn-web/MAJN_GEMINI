## 2. 주요 기술적 난제 및 의사결정 로그 (Decision Log)

### [결정 1] 공장 초기화(Blank Flash) 무한 리셋 원인 규명
- **현상**: 시리얼 포트 연결 시 `rst:0x10 (RTCWDT_RTC_RESET), boot:0x13 (SPI_FAST_FLASH_BOOT)`, `invalid header: 0xffffffff`가 0.03초마다 무한 반복됨.
- **원인 분석**: 칩 제조사에서 펌웨어가 적재되지 않은 빈 플래시(0xFF) 상태로 출고되어, CPU가 첫 부트 코드를 찾지 못하고 워치독에 의해 계속 재부팅된 현상이었음.
- **조치**: PlatformIO 기반으로 통합 팩토리 바이너리(`bootloader(0x1000)` + `partitions(0x8000)` + `boot_app0(0xe000)` + `firmware(0x10000)`)를 생성하여 플래싱함.

### [결정 2] DTR/RTS 부재 환경에서의 다운로드 모드 진입 전략
- **배경**: PCB 소형화를 위해 기판에 USB 통신 칩을 내장하지 않고 6핀 헤더(`UART_HDR`)로 분리함. 연결된 외장 CP2102 모듈에는 DTR/RTS 자동 리셋 라인이 없음.
- **실패 사례**: 파이썬 감시 스크립트가 포트를 점유한 채 `boot:0x03` 문자열을 대기하는 방식은 DTR 신호 혼선과 타이밍 불일치로 실패함.
- **최종 해결**: `IO0`(3번 핀)을 접지한 상태에서 `EN`(2번 핀)을 0.1초 접지하여 ROM Bootloader로 진입시킨 후, `esptool --before no-reset` 옵션으로 직접 sync 패킷을 전송하여 단 18초 만에 플래싱 완료.

### [결정 3] 파워온 리셋(POR) 잔류 전하 문제 및 기기 기동
- **현상**: 플래싱 후 일반 부팅을 위해 전원 케이블만 뺐다 꽂으면 ESP32가 켜지지 않고 침묵하는 현상 발생.
- **원인**: `C17` 커패시터(1µF)와 전원 라인의 잔류 전하로 인해 전압 강하가 0V까지 도달하지 않아 브라운아웃(Brownout) 대기 상태에 머묾.
- **조치**: `EN`(2번 핀)을 0.1초 접지하여 잔류 전하를 강제 방전시키자 즉시 정식 부팅되며 BLE 신호가 정상 방출됨.
- **향후 영구 해결책**: 
  1. 소프트웨어 원격 재부팅 명령 (`{"cmd": "REBOOT"}`) 펌웨어 반영
  2. 하드웨어 차기 리비전(Rev.C)에 자동 파워온 리셋(POR) IC 추가

### [결정 4] 무선 OTA(Over-The-Air) 업데이트 마일스톤 신설 (Phase 21)
- **배경**: 매번 펌웨어 수정 시마다 핀을 물리적으로 쇼트하는 것은 개발 및 유지보수 상 극히 비효율적임.
- **의사결정**: 마스터 개발 계획서(`docs/MAJN_MASTER_DEVELOPMENT_PLAN.md`)에 **Phase 21 (OTA Wireless Update)**를 공식 등록하고, 향후 웹 GUI 브라우저 또는 Wi-Fi를 통해 원클릭 무선 플래싱이 가능하도록 로드맵을 확정함.

## 3. 하드웨어 결선 상태 요약

### 1) UART 헤더 (`UART_HDR`)
- **1번 (`3V3`)**: 미사용 (보드 자체 5V 전원으로 LDO 구동)
- **2번 (`EN`)**: 수동 리셋 단자
- **3번 (`IO0`)**: 부트 모드 선택 단자
- **4번 (`TXD`)**: CP2102 RX 단자 연결
- **5번 (`RXD`)**: CP2102 TX 단자 연결
- **6번 (`GND`)**: CP2102 GND 공통 접지

### 2) 익사이터 출력 헤더 (`J1`, `J2`)
- **`J1` 단자 (상단 2핀)**: 채널 A BTL 출력 ➔ 익사이터 1번 쌍 (+, -)
- **`J2` 단자 (하단 2핀)**: 채널 B BTL 출력 ➔ 익사이터 2번 쌍 (+, -)
