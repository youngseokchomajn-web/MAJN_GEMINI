# MAJN 장애·트러블슈팅 일지

> 이 문서는 확인 가능한 기록의 시작점이다. 과거의 모든 터미널 출력이나 장치 로그가 자동으로 복구된 것은 아니다. 원문 로그가 없는 항목은 요약 기록으로만 취급한다.

## INC-2026-10-25-AMP-SUPERVISOR — 앰프 진단 및 안전 차단 감독 루프

- **기록 상태:** 커밋 diff 확인 / 실제 하드웨어 fault injection 결과 미확인
- **저장소:** youngseokchomajn-web/MAJN_GEMINI
- **관련 커밋:** [6ddf383](https://github.com/youngseokchomajn-web/MAJN_GEMINI/commit/6ddf38305b7d828c41f6921ac38f06b26e14ef7b)
- **관련 문서:** docs/MAJN_PHYSICAL_MEASUREMENT_AND_SAFETY_ASSESSMENT_PLAN.md
- **관련 코드:** 인증준비/firmware/src/main.cpp
- **보고된 빌드 결과:** 사용자가 esp32_full_hw 빌드 성공을 보고함. 이 기록 작성 과정에서 빌드를 독립적으로 재실행한 것은 아님.

### 관측 / 변경 내용
1. VibrationControlTask에 20 ms tick 5회마다 앰프 진단을 수행하는 감독 코드가 추가됨(명목상 약 100 ms 간격).
2. 앰프가 준비 상태이고 시스템이 활성화된 동안 getDiagnostics()가 실패하면 I²C 통신 실패로 판단해 MajnSafety::requestEmergencyStop()을 요청하도록 변경됨.
3. cFault 또는 gFault가 0이 아니면 같은 비상 정지 경로를 요청하도록 변경됨.
4. 문서에서 더미 부하 전력 계산을 전압 정의별로 분리함: 12 Vrms 기준과 12 Vpeak 정현파 기준은 서로 다른 전력값을 냄.
5. 문서는 실제 부하 전력을 차동 출력의 실효 전압과 부하 저항으로 계산하고, 온도 실측 없이 듀티사이클만으로 열 안전을 단정하지 않도록 수정됨.

### 아직 입증되지 않은 사항
- 실제 TAS5805M fault 또는 I²C 단절을 주입했을 때 셧다운이 발생하는지
- requestEmergencyStop()이 실제 하드웨어에서 AMP_PDN 및 BOOST_EN을 안전 상태로 만드는지
- gSafetyLock이 모든 START 경로를 차단하고, 원인 해소 전 재시작을 막는지
- I²C 호출 자체의 timeout과 스케줄링 지연을 포함한 최악의 셧다운 시간
- ESP32 task hang/reset 등 MCU가 감독 코드를 실행하지 못하는 경우의 독립 차단 여부
- 더미 부하의 실측 차동 전압, 실제 전력, 저항·방열판 온도
- 익사이터 구동 여부와 배시넷 패드 상면의 가속도/주파수 응답

### 다음 검증 절차
1. 실제 시험 보드 번호, PCB 리비전, 펌웨어 커밋과 바이너리 SHA-256을 기록한다.
2. 익사이터/더미 부하를 연결하기 전에 전원 레일, 배선, 부하 정격, 전류 제한 및 비상 차단 동작을 확인한다.
3. 안전한 저전력 시험 조건에서 정상 진단, I²C 읽기 실패, 보고 가능한 fault 상태를 각각 검증한다. 의도적 fault 주입은 장비·회로 손상 위험을 검토하고 통제된 조건에서만 수행한다.
4. 각 케이스에서 입력 조건, serial log, BLE 상태, AMP_PDN/BOOST_EN 실측 전압, 차단까지의 시간을 함께 기록한다.
5. 정상 상태 복귀 및 START 재시도 차단을 확인한다. 원인 해소·수동 복구 절차가 명확하지 않으면 반복 구동하지 않는다.
6. 더미 부하 시험은 차동 출력 전압을 안전하게 측정할 수 있는 적절한 계측기·프로브가 확보된 뒤 수행한다. 일반 접지형 오실로스코프 프로브를 BTL 출력에 임의 연결하지 않는다.
7. 패드 상면 진동은 센서 위치·축 방향·샘플링 주파수·필터 조건을 고정하고 원시 데이터를 저장한다.

### 현재 판정
**펌웨어 변경 기록은 확인되지만, 안전 차단의 실제 동작 및 물리적 진동 출력은 검증 대기 상태다.** 컴파일 성공만으로 하드웨어 fail-safe 또는 영유아 대상 안전성이 검증되었다고 판정하지 않는다.

## INC-2026-10-25-LOG-COVERAGE — 과거 로그 보존 범위

- **문제:** 모든 터미널/에이전트/장치 로그가 자동 보관되는 것으로 오해할 수 있음.
- **현재 확인 범위:** 이 대화에 사용자가 붙여넣은 로그·설명, GitHub에 실제 반영된 파일과 커밋은 확인 가능하다. 로컬 터미널의 전체 출력, BLE 세션의 원시 로그, 계측기 파일은 별도로 저장·공유되지 않았다면 확인할 수 없다.
- **조치:** 본 폴더에 기록 운영 기준과 이력을 마련한다. 이전 시험은 원본을 확보할 수 있을 때만 소급 등록하고, 복구할 수 없는 원시 로그는 ‘미확보’로 남긴다.
- **다음 조치:** 이후 시험부터 원시 로그 파일을 저장소에 추가하고, 요약 이력에 파일 경로와 커밋을 연결한다.


## INC-2026-10-25-PCB0005-MASTER-LOGBOOK — 마스터 로그북 통합

- **마스터 문서:** [MAJN PCB #0005 Master Troubleshooting & System Characteristics Logbook](../MAJN_PCB_0005_MASTER_TROUBLESHOOTING_AND_SYSTEM_CHARACTERISTICS_LOGBOOK.md)
- **관련 커밋:** [81bb9e5](https://github.com/youngseokchomajn-web/MAJN_GEMINI/commit/81bb9e592d8e8d45f953712d2507cc76adb63746)
- **기록 상태:** 문서와 소스 변경은 원격에서 확인. 실제 하드웨어 검증은 별도 확인 필요.

### 반영된 변경 이력
- TAS5805M 주소 및 I²S/앰프 초기화 순서에 대한 기록
- BLE OTA 전송 방식, 볼륨 레지스터 처리, 진폭 상한, fault 레지스터 읽기 순서에 대한 기록
- I²C Wire timeout 25 ms 설정
- BLE 명령 RESET_FAULT와 Safety Lock 중 파라미터 변경 차단
- 100 ms 간격으로 수행하는 앰프 진단 및 비상 정지 요청 코드

### 검증상 주의
1. 로그북의 12개 항목은 엔지니어링 변경 이력으로 보존하되, 각 항목의 실제 시험 증거가 모두 첨부되었다는 뜻은 아니다.
2. OTA 100% 무손실, fault 발생 시 완전 차단, RESET_FAULT의 모든 복구 경로, 실제 출력 진폭은 원시 시험 로그 또는 하드웨어 측정으로 별도 입증해야 한다.
3. 문서에 기재된 빌드 크기와 바이너리 파일 크기는 서로 다른 빌드 산출물 또는 시점일 수 있으므로 동일 바이너리라고 단정하지 않는다. 해당 빌드의 원문 로그와 SHA-256을 연결하기 전까지는 보고값으로 관리한다.
4. 100 ms 감독 주기는 보장된 최대 차단 시간이 아니다. I²C 타임아웃, 태스크 스케줄링, 긴급 정지 함수 실행시간을 포함한 최악 조건의 지연을 실측해야 한다.
5. BTL 출력의 차동 측정, 더미 부하의 열 안전, 패드 상면 가속도는 실물 계측 전까지 검증 대기다.
