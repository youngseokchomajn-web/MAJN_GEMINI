# MAJN 트러블슈팅 기록 운영 기준

## 목적
펌웨어 빌드, PCB bring-up, BLE 통신, 앰프 진단, 진동 출력, 전기·열·가속도 측정 기록을 한 곳에서 추적한다. 로그가 있다는 것과 시험을 통과했다는 것을 혼동하지 않으며, 실패·중단·재현 불가 결과도 삭제하지 않는다.

## 문서 구성
- [장애·트러블슈팅 일지](INCIDENT_LOG.md): 증상, 조건, 가설, 조치, 결과, 미해결 항목의 시간순 기록
- [빌드·시험 이력](BUILD_AND_TEST_HISTORY.md): 커밋, 빌드 환경, 바이너리 식별자, 보드 리비전, 시험 결과 연결
- logs/firmware/: ESP32 serial log, 빌드·플래시 출력, BLE/I²C/TAS5805M 진단 원문
- data/measurements/: 전류, 전압, 부하, 온도, 패드 표면 가속도·주파수 응답 등 원시 측정값
- docs/troubleshooting/templates/: 반복 사용 기록 템플릿

## 기록 원칙
1. **원문 보존:** 콘솔 출력과 실패 로그를 요약본으로 대체하지 않는다. 민감한 정보·토큰·개인정보는 저장 전에 제거한다.
2. **관측과 해석 분리:** 실제 출력, 계측값, 오류 메시지는 ‘관측’; 원인 추정은 ‘가설’; 검증된 원인은 ‘확인된 원인’에 기록한다.
3. **시험 단계 분리:** 컴파일 성공 ≠ 플래시 성공 ≠ BLE 동작 ≠ 앰프 출력 ≠ 익사이터 구동 ≠ 패드 표면 진동 측정 ≠ 영유아 효능·안전성 입증.
4. **재현 조건 필수:** 보드 번호/리비전, 펌웨어 커밋·바이너리 해시, 전원, 부하, 배선, 명령·설정, 측정기와 측정 위치를 가능한 범위에서 기록한다.
5. **실패도 결과:** 실패·중단·재현 불가를 남기고, 미확인 사항은 미확인으로 표시한다.
6. **기록 누락을 추정으로 메우지 않는다:** 기존 대화나 커밋 설명만 있는 내용은 ‘요약만 확인’으로 표시한다. 원시 로그가 실제로 확보되지 않았다면 로그가 저장됐다고 쓰지 않는다.
7. **측정값은 원본 단위와 함께 보존:** 계산·필터링·그래프는 별도 파생 파일로 저장하고 원시 데이터는 덮어쓰지 않는다.

## 파일 이름 권장
- 원시 로그: YYYY-MM-DD_board-0005_subsystem_test-id.log
- 측정 CSV: YYYY-MM-DD_board-0005_measurement_test-id.csv
- 요약: YYYY-MM-DD_incident-or-test-id_summary.md

시험 ID 예: FW-001, AMP-001, BLE-001, VIB-001, THERM-001.

## 시험 종료 시 체크
- [ ] 커밋 SHA와 보드 번호/리비전을 기록했다.
- [ ] 빌드 결과와 실제 장치 시험 결과를 각각 기록했다.
- [ ] 원시 로그/측정 파일 경로 또는 미확보 사유를 기록했다.
- [ ] 기대값, 실제값, 합격 기준을 구분했다.
- [ ] 안전 중단·예외·재시도 이력을 기록했다.
- [ ] 다음 조치와 담당자를 지정했다.

> 이 기록 체계는 개발 추적성을 위한 것이다. 그 자체로 제품의 안전성·성능·임상 효과를 보증하지 않는다.
