# MAJN 시제품 #0005 구동·BLE 화면·패드 진동 검증 계획

- 작성일: 2026-10-22
- 대상: 이미 생산된 PCB #0005 및 `bassinet_simulator`
- 목적: 기존 하드웨어를 먼저 정상 구동하고, 실물 제어 화면과 패드 상면 진동 측정의 근거를 확보한다.
- 원칙: 생산 PCB와 이후 설계 제안을 구분한다. 확인하지 않은 센서·전원·온도 값은 실측값처럼 표시하지 않는다. 아기에게 사용하지 않고 벤치 테스트로 검증한다.

## 우선순위 요약

1. P0 — 생산 보드의 실제 회로/BOM 및 측정 지점 확인
2. P0 — BLE 연결 후 진동자가 반응하지 않는 원인 분리
3. P1 — BLE 화면을 실물 제어에 필요한 요소만 남기도록 정리하고 실제 브라우저에서 검증
4. P1 — 패드 상면 가속도 측정 준비 및 반복 측정
5. P2 — 결과와 미해결 위험을 시제품 검증 기록으로 정리

UI 정리와 하드웨어 진단은 병행 가능하다. 진동 측정은 구동이 안정적으로 재현된 뒤 진행한다.

## 작업 1 — 생산 보드 기준 자료 확정

### 할 일
- PCB #0005에 실제 적용된 회로도, BOM, PCB 리비전, 조립 변경사항을 한 세트로 지정한다.
- 센서 실장 여부는 해당 생산 리비전의 BOM과 회로도에서 확인한다. 저장소의 최신 설계나 소프트웨어의 주석만으로 판단하지 않는다.
- 앰프 전원 레일의 실제 목표 전압, 측정 지점, TAS5805M PDN 핀, I²C 주소 설정 저항, 익사이터 연결 단자를 문서화한다.
- 생산 자료가 불명확한 항목은 “미확인”으로 남긴다.

### 완료 기준
- PCB #0005와 일치하는 자료 버전이 특정됨.
- 전원·PDN·I²C·출력 측정 지점을 회로도에서 확인하거나, 미확인 항목을 명시함.
- 센서 탑재 여부를 추정이 아닌 BOM/회로도로 판정함.

## 작업 2 — 진동자 무반응 원인 진단

### 순서
1. 현재 펌웨어 버전과 업로드한 빌드 환경을 기록한다. 진단 중에는 코드 변경을 최소화한다.
2. 실물 보드에 `esp32_full_hw` 펌웨어를 업로드하고 시리얼 로그를 저장한다(115200 baud).
3. 전원 OFF 상태에서 단락·커넥터·익사이터 배선과 극성을 확인한다.
4. 전원 ON 상태에서 회로도에 정의된 지점의 3.3 V 및 앰프 전원 레일을 멀티미터로 확인한다. 회로도 확인 전에는 앰프 레일이 12 V라고 가정하지 않는다.
5. BLE 연결 후 START를 누르기 전후의 시리얼 로그에서 I²C 스캔, TAS5805M 초기화 결과, PDN 상태, START 명령 처리 결과를 확인한다.
6. 앰프 초기화 실패, I²C 미응답, 전원 이상, 제어 명령 미수신, 앰프 출력/익사이터 경로 문제를 각각 분리한다.
7. 한 번에 하나의 원인만 수정하고, 매 변경 후 같은 테스트를 반복한다.

### 안전 및 주의
- 익사이터가 움직이지 않는다는 이유만으로 앰프 출력을 임의로 단락하거나 접지하지 않는다.
- BTL 출력 단자에는 접지형 오실로스코프의 그라운드 클립을 직접 연결하지 않는다.
- 측정 지점은 생산 회로도 기준으로 정한다.
- 영아나 사람을 태운 상태에서 테스트하지 않는다.

### 완료 기준
- BLE START/STOP을 반복해도 보드 상태와 명령 결과가 일관됨.
- 진동자가 실제로 반응하거나, 무반응 원인이 관찰 증거와 함께 특정 단계까지 좁혀짐.
- 성공 여부를 UI의 RUNNING 표시만으로 판단하지 않고, 실제 진동 여부를 별도로 확인함.

## 작업 3 — BLE 제어 화면 정리

### BLE 실물 모드에 남길 항목
- BLE 연결 상태 및 실물 장치 이름
- 제어 상태(READY/RUNNING/FAULT 등)
- 진동 주파수 설정(현재 펌웨어에서 지원하는 범위 내)
- 진동 강도 설정(현재 펌웨어에서 지원하는 범위 내)
- START, STOP, 비상 정지
- 명령 ACK/오류 중심의 통신 로그

### BLE 모드에서 숨기거나 제거할 항목
- 가상 배시넷 애니메이션과 가상 아기 상태
- IMU 그래프 및 센서 스트림 표시(실물 보드에 센서와 실제 데이터 경로가 확인되지 않았으므로)
- 실측되지 않은 PVDD·3.3 V·앰프 온도 값
- 검증되지 않은 AI 자동 달래기/폐루프 제어 표현
- 현재 작업에 필요하지 않은 OTA 업데이트 패널과 원격 재부팅 버튼

시뮬레이터 모드의 기능은 별도로 유지한다. OTA는 전송·복구 절차를 검증하기 전까지 실물 제어 화면의 기본 요소로 노출하지 않는다.

### UI 검증 시나리오
- 데스크톱 Chrome과 실제 사용하는 모바일 브라우저에서 접속한다.
- 시뮬레이션 → BLE → 시뮬레이션 전환 시 각 화면이 올바르게 복원되는지 확인한다.
- 연결 성공, 연결 취소, 연결 끊김, START/STOP, 명령 거부/오류 상태를 확인한다.
- BLE 화면에서 센서·전원·온도 측정값을 사실처럼 보여주지 않는지 확인한다.
- 모바일 화면에서 비상 정지 버튼이 잘 보이고 눌리기 쉬운지 확인한다.
- 비상 정지는 시각적 강조뿐 아니라 실제 ESTOP 명령 전송 및 보드 반응으로 검증한다.

### 완료 기준
- 실물 제어와 무관한 패널이 BLE 모드에서 보이지 않음.
- 명령을 보냈다는 사실과 장치가 명령을 실제 적용했다는 사실이 구분됨.
- 연결 끊김·오류가 화면에 명확하게 나타남.
- 시뮬레이터 기능은 BLE 모드 정리로 손상되지 않음.

## 작업 4 — 패드 상면 진동 측정

### 측정 준비
- 외부 가속도계와 데이터 수집 장비를 사용한다. PCB에 센서가 있는지는 패드 상면 측정을 대체하지 않는다.
- 센서를 패드 상면의 지정 위치에 반복 가능한 방식으로 고정한다.
- 센서 축 방향, 고정 방법, 패드/프레임 조립 상태, 전원 조건을 기록한다.
- 측정 장비의 범위와 샘플링 주파수가 측정하려는 진동 주파수와 고조파를 충분히 포착할 수 있는지 확인한다.

### 측정 절차
1. 구동하지 않은 상태의 기준 신호와 장비 노이즈를 기록한다.
2. 가능한 범위에서 한 가지 주파수·강도 조건씩 설정한다.
3. 각 조건에서 안정화 후 시간 신호를 기록하고 반복 측정한다.
4. 주파수별 가속도 크기와 주파수 스펙트럼을 산출한다.
5. 설정값과 측정값이 일관되게 대응하는지, 조건 변경 시 진동이 재현되는지 확인한다.
6. 패드 위치나 조립 상태를 바꿨다면 별도 조건으로 기록한다.

### 반드시 기록할 정보
- PCB/펌웨어 버전
- 패드 및 프레임 구성
- 센서 모델, 감도, 축 방향, 고정 방식
- 샘플링 주파수와 측정 시간
- 설정 주파수·강도
- 측정 가속도와 주파수 성분
- 반복 횟수, 측정 중 오류, 주변 조건

### 완료 기준
- 측정 위치와 방법을 다시 재현할 수 있음.
- 설정별 측정 결과와 반복 편차를 기록함.
- 현재 시제품에서 재현 가능한 동작 범위와 추가 검증이 필요한 범위를 구분함.

이 측정은 시제품의 기계적 진동 특성을 파악하기 위한 것이다. 영아 안전성, 진정 효과, 수면 개선 효과를 입증하는 자료로 간주하지 않는다.

## 작업 5 — 검증 결과 정리 및 다음 의사결정

결과는 아래 세 가지로 분류한다.

- **확인됨:** 실제 로그·측정값·생산 자료로 확인한 사실
- **미확인:** 자료나 측정이 부족해 결론을 내릴 수 없는 항목
- **실패/위험:** 반복 재현되는 오류 또는 안전상 추가 검토가 필요한 항목

최종 기록에는 다음을 포함한다.
- PCB #0005에서 실제 동작하는 기능
- BLE 연결 및 명령 처리 결과
- 진동 무반응 원인과 수정 내역
- 패드 상면 측정 방법과 결과
- 남아 있는 하드웨어·소프트웨어·안전 검증 항목
- 다음 설계 변경이 필요한지 여부와 근거

## 현재 즉시 할 일

1. PCB #0005와 일치하는 회로도/BOM을 확보하고 센서 및 측정 지점을 확정한다.
2. 이미 수정한 펌웨어를 기준으로 시리얼 로그를 수집한다.
3. 보드가 실제로 진동하는지 확인하기 전까지 회로 변경이나 센서 추가를 서두르지 않는다.
4. BLE 화면은 실측 데이터와 가상 데이터가 섞이지 않도록 검증한다.
5. 진동 구동이 재현되면 외부 가속도계로 패드 상면 측정을 시작한다.
