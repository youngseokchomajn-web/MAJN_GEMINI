# MAJN_GEMINI 인증/EMC 사전검토 세션 종합 기록 — 2026-10-06

## 0. 문서 목적

2026-10-06 세션에서 수행한 MAJN_GEMINI 하드웨어의 인증 준비, EMC 사전검토, 계측장비 구매 판단, 실제 PCB geometry 분석, 위험도 판정, 수정 우선순위 및 후속 시험 전략을 하나의 기준 문서로 통합한다.

## 1. 최종 결론

현재 가장 중요한 결론은 다음과 같다.

1. **지금 EMC 계측장비를 비싸게 선구매하지 않는다.**
2. 현재 보유한 멀티미터로 기본 전원/브링업을 계속한다.
3. 회로도 → BOM/netlist → 실제 PCB copper/geometry 순으로 설계를 먼저 검토한다.
4. 실제 PCB 분석 결과 가장 먼저 수정 검토할 대상은:
   - MP3426 BOOST_SW switching loop
   - TAS5805M A채널 BTL 출력
   - 외부 actuator cable/common-mode 경로
5. **L1/D3의 실제 의도 부품과 현재 netlist/BOM 정의가 서로 맞지 않는 문제는 제작 전 반드시 해결한다.**
6. BOOST loop 수정 후 PVDD_12V 및 TAS5805M local decoupling/GND return을 추가 검토한다.
7. 그 다음 prototype → EMC Pre-test → 실패 주파수/동작조건 확인 → 필요한 대책 → 재시험 순서로 간다.
8. 오실로스코프, spectrum analyzer, EMI receiver, current probe 등을 지금 사는 것은 우선순위가 낮다. Pre-test 결과에 따라 필요한 장비만 구매/대여한다.
9. 자체 시뮬레이션/설계검토는 위험 감소에는 유효하지만 실제 RE/CE 수치나 KC/전파 적합성을 확정할 수는 없다.

# 3. 인증/시험에 대한 의사결정

## 3.1 계측장비

### 현재 보유

- 멀티미터 1대

### 지금 구매하지 않기로 한 장비

- 오실로스코프
- Spectrum Analyzer
- EMI receiver
- Current probe
- LISN
- GTEM/TEM cell

### 이유

아직 실제 EMC failure frequency나 원인이 확인되지 않았다.

현재는 PCB layout과 current loop 자체에서 줄일 수 있는 위험이 명확하다. 따라서 비싼 계측장비를 먼저 사는 것보다:

**설계 검토 → PCB 수정 → prototype → EMC Pre-test**

가 비용 효율적이다.

Spectrum analyzer 하나를 구매한다고 해서 공인 EMC 시험을 대체할 수도 없다.

### 장비 추가 구매/대여 조건

Pre-test에서 특정 주파수, switching harmonic, ringing, conducted noise 등이 확인될 경우 그 원인에 맞는 장비를 선택한다.

# 4. EMC 위험도 1차 판정

## HIGH

### 4.1 MP3426 BOOST_SW / switching loop

가장 우선적인 설계 수정 후보.

이유:

- boost converter의 고속 switching node
- 높은 di/dt
- switching current loop가 EMI source가 되기 쉬움
- 현재 실제 PCB에서 SW 경로가 비교적 길게 형성됨

### 4.2 TAS5805M Class-D A채널

- A+ 약 26.0 mm
- A- 약 39.4 mm
- 두 경로의 layer transition 및 routing 환경이 상당히 다름
- J1 외부 cable로 연결됨

BTL 출력이므로 단순히 선 길이가 다르다는 사실만으로 실패를 확정할 수는 없다. 다만 외부 케이블로 나가는 고속 출력이므로 common-mode coupling 관점에서 우선 검토한다.

### 4.3 외부 actuator cable

PCB 밖으로 나가는 긴 도선은 EMC에서 중요한 변수다.

실제 cable 길이, 배치, 부하, 출력 조건에 따라 방사/공통모드 노이즈가 크게 달라질 수 있다.

### 4.4 4 actuator 동시 구동

최대 출력 및 switching activity가 발생하는 worst-case 후보.

### 4.5 Boost + Class-D 동시 동작

전원 switching noise와 Class-D switching noise가 동시에 존재하므로 전원/ground coupling을 확인해야 한다.

## MEDIUM-HIGH

- AMP_OUT_B
- PVDD_12V
- USB-C VBUS_5V
- ESP32 RF와 noisy power/audio 영역의 coupling

## LOW-MEDIUM

- 3.3 V LDO
- MCU/IMU power
- LSM6DSOX 자체는 주요 EMI source보다는 noise-sensitive block

- center: (2263.8, 1181.1)
- VBUS_5V-GND
- 4.7 uF

판정:

# 7. 제작 전 반드시 해결해야 할 데이터 정합성 문제

## L1 / D3 BOM-netlist 불일치

현재 pcb_netlist_final.json에서는:

- L1 = WR04X5601FTL / 5.6 kOhm / R0402로 표시
- D3 = RN731JTTD3901B25 / 3.9 kOhm / R0603로 표시

그러나 설계 의도 및 기존 관리 정보에서는:

- L1 = 4.7 uH boost inductor
- D3 = SS34 boost diode

로 되어 있다.

또한 net geometry에는 명확히 BOOST_SW가 존재하고 U3는 MP3426DL이다.

따라서 단순 표기 오류인지, 실제 schematic/BOM/PCB revision mismatch인지 확인해야 한다.

### 결정

**P0: L1/D3 부품 정의를 schematic → PCB → BOM → PnP → 제조용 데이터 전체에서 정합화한 뒤 제작한다.**

정합성이 해결되기 전에는 새 좌표를 확정하거나 제조 데이터를 확정하지 않는다.

이 이슈는 EMC 문제이면서 동시에 제조/기능상 치명적인 revision 관리 문제다.

# 8. TAS5805M Class-D 출력 검토

## A채널

- AMP_OUT_A+: 약 26.0 mm
- AMP_OUT_A-: 약 39.4 mm
- 약 13.4 mm 차이
- A-는 긴 Bottom/inner-layer 경로 포함

판정:

**P1 — 경로 환경 대칭화 검토**

목표:

- A+/A-의 물리적 환경을 최대한 비슷하게
- 불필요한 layer transition 감소
- J1까지 짧고 예측 가능한 routing
- 출력 pair 주변 return/GND 환경 확인
- connector에서 common-mode 대책을 추가할 수 있는 공간 확보

중요:

BTL은 차동 출력이므로 raw length mismatch만으로 EMC failure를 단정하지 않는다. 실제로는 pair의 coupling, layer/plane 환경, connector/cable common-mode conversion을 같이 본다.

## B채널

- AMP_OUT_B+: 약 14.1 mm
- AMP_OUT_B-: 약 16.5 mm

A채널보다 균형이 좋다.

현재는 대규모 수정 대상보다 관찰 대상으로 둔다.

# 12. 외부 actuator cable

J1/J2가 보드 외곽에 위치하고 Class-D 출력이 외부 케이블로 나간다.

이 구조는 EMC에서 매우 중요하다.

Pre-test에서는 다음을 실제 조건으로 유지한다.

- 실제 제품 cable 길이
- 실제 actuator
- 4개 동시 구동
- 최대 정상 출력
- Boost ON
- ESP32 통신 ON
- 실제 USB-C 외부전원
- 최종 enclosure/배선 조건

필요할 경우 connector 근처에서 ferrite/common-mode 대책을 추가할 수 있도록 PCB 공간을 확보한다.

# 14. 시뮬레이션으로 할 수 있는 것

설계 단계에서 다음은 검토 가능하다.

- current loop/return path 분석
- decoupling 구조
- boost switching harmonic/ripple의 상대적 위험 비교
- filter/ferrite 역할 비교
- noisy zone 분석
- cable/common-mode coupling 위험 비교
- 필요 시 SPICE 기반 전원/필터 검토

하지만 다음은 시뮬레이션만으로 확정할 수 없다.

- 실제 RE/CE 수치
- 실제 케이블/케이스를 포함한 방사 특성
- 실제 시험소 환경에서의 EMC 합격
- KC/전파 적합성평가 결과

따라서 시뮬레이션은 **사전 설계검토 도구**로 사용하고, 최종 판단은 실제 Pre-test와 공식 시험으로 한다.

# 17. 의사결정 원칙

### 결정 1
**EMC 장비를 지금 사지 않는다.**

근거: 현재 설계에서 먼저 줄일 수 있는 위험이 명확하고, 실제 failure frequency가 아직 없다.

### 결정 2
**실제 PCB geometry를 기준으로 설계수정을 판단한다.**

근거: 회로도만으로는 trace length, layer transition, plane, connector/cable coupling을 판단할 수 없다.

### 결정 3
**BOOST_SW를 최우선 수정 후보로 둔다.**

근거: 실제 geometry에서 약 20.4 mm의 switching path가 확인됐고, U3/L1/D3가 넓게 배치되어 있다.

### 결정 4
**Class-D A채널을 P1로 둔다.**

근거: A+/A- routing 환경 차이가 크고 외부 cable로 연결된다. 다만 BTL 특성상 단순 길이 차이만으로 실패를 단정하지 않는다.

### 결정 5
**L1/D3 BOM-netlist mismatch를 P0로 승격한다.**

근거: 의도한 부품과 현재 netlist 정의가 다르므로 EMC 이전에 제조 데이터의 기본 정합성이 확보되지 않은 상태다.

### 결정 6
**정확한 새 좌표는 L1/D3 정합성 해결 후 결정한다.**

근거: footprint와 실제 부품 정의가 확정되지 않은 상태에서 좌표를 확정하면 다시 설계를 뒤집을 가능성이 있다.

### 결정 7
**Pre-test를 공식 시험 전에 반드시 활용한다.**

근거: 실제 PCB + cable + enclosure + load 조건에서만 확인할 수 있는 EMI 요소가 존재한다.

### 결정 8
**Pre-test 실패 후 장비를 추가한다.**

근거: 실패 대역과 operating mode를 알면 필요한 계측장비를 좁힐 수 있다.

# 22. 2026-10-06 후속 확인 — SSOT와 실제 PCB Master의 역할 분리

추가 확인 결과 `인증준비/mcp_development/mcp_design_flow.json`은 **project version 1.9.2 SSOT**이며 현재 component 정의에서 다음을 명시하고 있다.

- L1 = Boost Inductor 4.7 uH, LCSC C78804, SMD-5.0x5.0
  - pin 1 = VBUS_5V
  - pin 2 = BOOST_SW
- D3 = Boost Schottky Diode SS34, LCSC C8678, SMA-DO-214AC
  - pin 1 = PVDD_12V
  - pin 2 = BOOST_SW
- U3 = MP3426DL
- BOOST_SW = U3 pins 4/5/6 + L1 pin 2 + D3 pin 2

따라서 현재 판단은 **L1/D3를 새 부품으로 선정해야 한다는 것이 아니라, SSOT의 의도 부품 정의와 실제 EasyEDA PCB/BOM/PnP/netlist export 사이의 정합성을 먼저 확인해야 한다는 것**으로 정정한다.

특히 현재 repo README의 기준에 따라 EasyEDA Pro cloud의 `new start / Board1 / PCB1`이 실제 PCB master이므로, GitHub의 SSOT만 보고 새 PCB 좌표를 임의 확정하지 않는다.

### 다음 실제 작업

1. EasyEDA Pro에서 최신 `PCB1`의 L1/D3 footprint 및 속성 확인
2. L1 = C78804 / 4.7 uH / SMD-5.0x5.0인지 확인
3. D3 = C8678 / SS34 / SMA-DO-214AC인지 확인
4. 같은 PCB revision에서 BOM / PnP / netlist를 다시 export
5. SSOT v1.9.2와 비교
6. 정합성이 확인된 뒤에야 U3-L1-D3 실제 placement/routing을 확정
7. 그 다음 BOOST_SW loop와 C5 VIN/GND loop를 실제 geometry 기준으로 수정

**중요:** 현재 GitHub에서 실제 EasyEDA cloud PCB를 직접 수정한 것은 아니다. 지금까지는 설계 판단과 의사결정 로그를 업데이트한 상태이며, 실제 PCB 변경은 최신 EasyEDA PCB source/export를 확인한 뒤 수행한다.

# 23. 2026-10-06 후속 확인 — EasyEDA Cloud 실제 PCB 접근 경로

이번 세션에서 사용자가 **EasyEDA Cloud의 실제 프로젝트 초대 링크**를 제공했다.

현재 확인 결과:

- Cloud 초대 링크 자체를 이 환경에서 직접 열어 PCB 객체/geometry를 읽는 것은 불가능했다.
- 따라서 **Cloud PCB를 실제로 읽었다고 간주하거나, 링크만으로 현재 PCB 상태를 추정하지 않는다.**
- 대신 repository 내부에 이미 **EasyEDA Pro ↔ AI Agent 연동을 위한 로컬 Bridge/API 파이프라인**이 존재하는 것을 확인했다.

## 확인된 기존 접근 구조

`인증준비/mcp_development/README_AI.md` 기준:

```text
AI Agent / Python
      ↓ HTTP POST
Bridge Server :49620
      ↕ WebSocket
EasyEDA Pro Editor
      ↓
현재 열려 있는 PCB
```

관련 기존 구성:

- `easyeda-api-skill/`
- `easyeda_mcp_client.py`
- `run_mcp_design_flow.py`
- `run_full_drc.py`
- `run_export_gerber.py`
- `mcp_design_flow.json`
- EasyEDA Pro `run-api-gateway` 확장 사용 절차

즉, 별도의 새로운 PCB 분석 시스템을 만들 필요가 없다. **사용자의 EasyEDA Pro에서 Cloud의 최신 PCB1을 열고 기존 Bridge/API 경로를 연결하면 현재 PCB를 직접 읽어오는 방식으로 검토를 이어갈 수 있다.**

## 실제 PCB 확인 원칙

다음 단계에서는 GitHub의 과거 Gerber/BOM/PnP/netlist만으로 현재 PCB를 확정하지 않는다.

1. EasyEDA Pro에서 Cloud의 최신 PCB1을 연다.
2. 기존 `run-api-gateway` + Bridge Server 경로를 연결한다.
3. 현재 열린 PCB에서 L1/D3의 실제 footprint/속성/좌표/net을 읽는다.
4. `mcp_design_flow.json v1.9.2`의 SSOT와 비교한다.
5. 필요하면 동일 revision의 BOM/PnP/netlist를 다시 export한다.
6. 정합성이 확인된 뒤 실제 BOOST_SW geometry를 재판정한다.
7. 그 결과를 기준으로만 좌표/배치 수정안을 확정한다.

## 이번 단계의 결론

**현재는 EasyEDA Cloud 프로젝트의 존재와 초대 링크까지 확보했지만, 이 환경에서 Cloud PCB 자체를 직접 읽은 상태는 아니다.**

따라서 현재 판단은 다음처럼 유지한다.

- L1/D3를 임의로 교체하거나 새 부품으로 확정하지 않는다.
- 새 좌표를 먼저 확정하지 않는다.
- 현재 GitHub의 historical PCB data는 참고자료로 사용한다.
- **Cloud의 최신 PCB1을 EasyEDA Pro에서 실제로 읽은 뒤 L1/D3 → BOOST loop → C5 VIN loop 순으로 검증한다.**

이 단계가 완료되면 **'과거 export 기준 분석'에서 '현재 Cloud PCB master 기준 분석'으로 검토 기준을 승격**할 수 있다.
