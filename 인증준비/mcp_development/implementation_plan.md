# [목표]
부품 간의 물리적 거리(Routing Channel) 부족 현상을 해결하기 위해 부품 배치를 다각적으로 재조정(Relayout)하고, 넓어진 기판 위에서 파이썬 기반의 오토라우팅을 수행하여 100% 에러 없는 배선을 완성합니다.

> [!CAUTION]
> 사용자 개입 0% 원칙을 준수하기 위해 이전의 '수동 조작 계획'을 전면 폐기하고, AI 에이전트가 직접 부품 간격을 벌리고 길찾기 알고리즘을 구현합니다.

## 잠재적 허점 및 에러 발생 원인 (Critical Review)

계획을 꼼꼼히 재검토한 결과, 4가지 치명적인 허점(Loopholes)과 에러 유발 가능성을 발견하였으며 이를 차단하기 위한 대비책을 세웠습니다.

### 1. 부품 재배치 시 기존 파워 라인의 '공중 부양' 문제
- **허점:** 부품의 위치를 강제로 넓히면(Relayout), 기존에 1.0~1.2mm로 연결해두었던 파워 라인(VBUS, PVDD)들이 부품을 따라가지 못하고 허공에 떠버려 수백 개의 연결 에러(Connection Error)를 발생시킵니다.
- **대비책:** 부품 재배치 스크립트를 실행하기 직전에 **모든 파워 라인과 비아를 완전히 삭제**하고, 부품 배치가 끝난 새로운 좌표를 기반으로 `route_power.py`를 재실행하여 파워 라인을 처음부터 다시 깔아야 합니다.

### 2. 회로도 업데이트 시 '빈 구멍(Via)' 부활 현상
- **허점:** 만약 기판 데이터를 갱신하기 위해 회로도에서 'Import Changes(변경사항 가져오기)'가 실행될 경우, 오토라우터를 뻗게 만들었던 U4(오디오 앰프) 내부의 텅 빈 열 방출 구멍(Via) 11개가 다시 살아납니다.
- **대비책:** 제가 작성할 파이썬 오토라우터 스크립트 도입부에 **"Net 속성이 비어있는 Via를 무조건 찾아내 삭제하는 클리너(Cleaner) 로직"**을 최우선으로 삽입하여, 언제든 에러 요인이 부활하는 것을 원천 차단합니다.

### 3. A* 오토라우터의 '안테나 간섭' 및 '노이즈' 문제
- **허점:** 제가 직접 짜는 파이썬 오토라우터가 단순히 '최단 거리'만 찾게 될 경우, ESP32 안테나 바로 아래로 선을 지나가게 하거나(통신 불량), 스위칭 노이즈가 심한 부스트 라인을 오디오 라인과 겹치게 그을 위험이 있습니다.
- **대비책:** 알고리즘의 2D 그리드 맵에 ESP32 안테나 하단 영역을 **'절대 진입 금지 구역(Keep-out Zone)'**으로 마킹하고, 노이즈 민감도를 반영하여 전원선 ➔ 오디오선 ➔ 일반 디지털 신호선 순서로 가중치를 두어 배선하는 로직을 추가합니다.

### 4. 이격거리(Clearance) 연산 오류로 인한 미세 겹침
- **허점:** 파이썬 그리드 라우터가 선 두께와 안전거리(0.25mm)를 정밀하게 계산하지 못하면 겉보기엔 안 겹쳐도 DRC 검사에서 겹침 에러(Clearance Error)가 터질 수 있습니다.
- **대비책:** 모든 패드와 기배선된 라인의 좌표를 마킹할 때, 선 두께의 절반 + 안전거리(0.25mm)를 더한 반경(Radius)만큼 그리드 셀을 팽창(Dilation)시켜 '가상의 범퍼'를 만든 뒤 그 바깥으로만 길을 찾도록 알고리즘을 강화합니다.

## 제안하는 변경 사항 (최종)
1. **정화 및 확장:** 전체 배선 초기화 ➔ Net 없는 불량 Via 강제 삭제 ➔ 기판 80x50mm 확장 ➔ 부품 간격 1.5배 재배치
2. **우선 배선:** 기판 외곽선 자동 작도 ➔ 두꺼운 파워 라인(VBUS, PVDD) 선행 배선 및 Keep-out 영역(ESP32) 설정
3. **지능형 라우팅:** Python 2D Grid A* 알고리즘 구동 (안전 범퍼 팽창 적용, 100% 자율 배선)
4. **최종 검증:** 네이티브 DRC 검사를 통한 에러 0개 달성 확인.
