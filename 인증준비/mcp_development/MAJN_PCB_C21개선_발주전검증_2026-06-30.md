# MAJN PCB — C21 개선 + 발주 전 Fresh-Eye 전수검증 (2026-06-30)

대상: EasyEDA Pro `new start` / PCB1. 본 기록은 PCB(클라우드 저장)에 적용된 변경과 발주 전 검증 결과를 문서화한 것이다.

## 1. C21 부스트 VCC 바이패스 클린 개선 (6.8mm → 1.78mm, DRC 0 유지)

**목적**: MP3426(U3) 내부 VCC 핀(U3.7)의 디커플링 캡 C21을 핀 정면으로 근접시켜 루프 인덕턴스/EMI 저감 (E-05 디커플링 결함의 C21 부분 해결).

**결과**: VDD 패드 → U3.7 거리 **6.8mm → 1.78mm (74% 단축)**, DRC 0 유지.
- C21 배치: (440,1874) 0° → **(624,1820) 180° 회전**, C21.1(BOOST_VDD)@(652,1820), C21.2(GND)@(596,1820).

**방법(재현용 절차)**:
1. **종합 클리어런스 탐색** — 캡 패드뿐 아니라 VDD 비아 + Inner2 트레이스 + GND 비아까지 **전부 ≥6mil(캡 ≥8mil)** 검사. VDD 좌/우(=회전 vs±1) 포함. → (624,1820) 전 요소 클린(캡8.3·VDD비아25.6·GND비아22·트레이스41.4mil) 확인.
2. `pcb_PrimitiveComponent.modify(id,{x,y,rotation})` 로 이동+180° 회전. **★회전이 영속됨**(setState_Rotation은 안 됨, modify는 됨).
3. 재라우트: VDD via@패드 → Inner2 트레이스 → 기존 via@(635,1770) → U3.7 / GND via@반대패드.
4. `pour.rebuildCopperRegion()` 재pour → 권위 UI DRC 확인.

**과정 함정 2건(교훈)**:
- **(A) 고아 비아**: 부품 이동 시 옛 패드 밑 Top↔Inner 비아가 끊긴 채 잔존 → Connection Error. flood-fill은 패드 없는 via-only 컴포넌트를 필터링해 못 잡음 → **권위 DRC만 적발**. 이동 후 옛 비아 삭제 필수.
- **(B) 과삭제**: 옛 위치 근처 GND 트랙/비아를 "고아"로 단정 삭제 금지 — 인접 부품(R9.2·C5.2)의 GND 평면 본딩일 수 있음. 과삭제로 2패드 floating섬 발생 → 그 섬 트랙 위 깨끗한 점(445,1764)에 GND 비아 1개 추가로 평면 재본딩.

## 2. 마운팅홀 4개 추가

## 4. 발주 전 Fresh-Eye 전수검증 (DRC 배제, 독립 기하/전기)

### ① 작동 측면 — PCB/회로 설계상 결함 0
- **연결성**: 신호넷 개방 0 · 단락 0(의심 3건=부품회전 미반영 AABB 거짓양성) · 부동핀 0.
- **IC 핀배열(5개 전부 데이터시트 대조)**:
  - U1 ESP32-WROOM-32UE — 부트스트랩 전수 정상(IO0↑·**IO12 NC=내부PD↓=3.3V플래시**·IO15=AMP_PDN/R13↑·IO5=SPI_CS/R14↑).
  - U2 AP2112K-3.3 — VIN1/GND2/EN3(VIN연결=상시ON)/NC4/VOUT5.
  - U3 MP3426 — **6A/35V 비동기 부스트**(내부 로우사이드 스위치 + 외부 D3 SS34 정류 필수, 정방향 ✓). FB R1(143k)/R2(16k)→12.17V.
  - U4 TAS5805M — PVDD×4·DVDD·내부레귤(VR_DIG/AVDD) 디커플링·I2S·I2C·PDN·부트스트랩·BTL출력.
  - U5 LSM6DSOX — 4선 SPI(CS12/SCLK13/MOSI14/MISO1)·INT1·VDD/VDDIO 3.3V·INT2(9)=NC.
- **전원 시퀀싱**: USB5V→LDO3.3V(상시)→ESP부팅→BOOST_EN(R11풀다운=기본OFF)으로 12V→I2C 앰프설정.
- **풀업/풀다운**: I2C R7/R8↑·EN R5+C17·IO0 R6↑·PDN R13↑·CS R14↑·BOOST_EN R11↓·ADR R12.
- **디커플링**: PVDD 0.5mm·BOOST_VDD 1.8mm·내부레귤 캡 有.
- **출력**: 페라이트(FB1~4)+2.2nF(C24~27)→J1/J2 양 트랜스듀서.

**작동 단서(펌웨어/통합 의존, HW결함 아님)**:
- 출력 필터리스 → 펌웨어 Fsw384kHz+확산스펙트럼+BD변조 설정 필수(TI: PVDD<14V면 페라이트 OK, 우리 12.1V).
- L1 Isat 5.5A vs 이론최대 피크 ~5A = 마진 10%(약한 진동엔 무방, 펌웨어 출력제한 권장).
- AMP_ADR(R12→3.3V) I2C 주소가 펌웨어 기대값(0x2C) 일치 확인.

### ② 인증 측면 — PCB 차원 결격 0, 프로세스 항목 잔존
유리: SELV(USB5V) 입력 · TVS(D1) 보호 · **ESP32-WROOM-32UE 사전인증 RF모듈**(전파인증 승계) · TAS5805M 저EMI.
**인증 전 처리(대부분 프로세스/펌웨어)**:
1. RF/안테나 — -32UE 외장 u.FL: KC인증 안테나 선정 + 모듈 전파인증 승계 문서화.
2. EMC 방사 — Class-D 페라이트출력 + 부스트 SW pour(E-04): 사전 EMC 스캔 + 펌웨어 EMI설정 + 트랜스듀서 리드 짧게.
3. **매트리스 밑 열(안전 핵심)** — 최대 의도출력 열영상 검증 + 펌웨어 전력제한.
4. 어린이제품 유해물질 — 부품 RoHS/프탈레이트 선언(BOM 차원).
5. 보드치수 83.8×62.2 vs 80×60 — 외함 정합 확인.

> **전파인증 메모**: 무선 부품(ESP32)이 실장된 한, BLE를 펌웨어에서 안 켜더라도 전파인증 대상(소프트웨어로 끈 것은 면제 근거 아님). 단 -32UE 사전인증 모듈 승계로 부담 경감. 면제하려면 무선 칩 자체를 제거해야 함.
