# 마중 PCB 작업 — 과정 오류·실수·도구한계 전수 정리 (2026-06-27)

PCB 자체 결함(E-01~E-15)은 `MAJN_에러케이스_정리_2026-06-27.md` 참조.
이 문서는 **작업/검증 과정에서 발생한 오류**(내 분석오판·도구한계·비영속작업·환경문제·스크립트버그·설계 근본원인)를 회고로 정리. ID = P-xx.

## A. 분석 방법론 오류 — 내 검증 로직의 거짓양성/오판 ★가장 중요

### P-01. 1차 연결성 flood-fill 버그 (거짓 개방 25건)
- 노드를 **패드/비아만** 사용, **트레이스 접합부(line endpoint) 누락** → 25건 거짓 개방 산출.
- 수정: line endpoint를 노드로 추가.

### P-02. VCC flood-fill 과분할 (거짓 고립)
- C10.1·C11.1·U5.5·U5.8·UART_HDR.1·R14.2를 "고립"으로 오판 → 실제론 전부 ~0mil 구리 접촉. via/멀티레이어 연결을 못 잡음.
- 권위 DRC는 VCC×2(R12 아티팩트)만 플래그.

### P-03. union-find가 동일 거짓양성 재현 (이번 세션)
- AMP_ADR·AMP_OUT_A-·SPI_CS·GND·VCC를 "5개 개방"으로 표시 → **직접 갭분석 결과 전부 구리가 패드에 접촉(연결됨)**. union-find 자체 버그(AMP_ADR는 연결 트레이스가 있는데도 분리로 나옴, 원인 규명 못 함).

### P-04. "실제 개방 0건"·"아티팩트" 주장 오류 → 정정
- 초기 단정이 틀렸음을 인정. **"왜 자꾸 말이 달라"** 피드백 받음. 이후 권위 DRC + 직접 갭분석을 진실원으로 채택.

> **★교훈**: 연결성은 union-find/flood-fill(pour·멀티레이어·tol 못잡음) 신뢰 불가. **직접 갭분석**(넷별 패드의 최근접 구리 gap; ≤-5mil=트레이스가 패드 덮음=연결) 또는 권위 DRC만 신뢰.

## 핵심 교훈 (다음 작업용)
1. **연결성 = 직접 갭분석/권위 DRC.** 내 union-find/flood-fill은 거짓양성 양산.
2. **영속/비영속 구분** 필수. component setState·풋프린트정의 비아는 복귀.
3. **DRC 의존 말고 전 도메인 기하검증** (단락·개방·극성·전력·EMI·열·기구) — 사용자 원칙과 일치.
4. **autoroute 완료율 위해 IC 인접 재배치 → PI/EMI 결함 발생.** 배치는 데이터플로+전원무결성 동시 고려.
5. **브릿지 기동 순서**: node bridge-server.mjs → EasyEDA PCB 열기 → API Gateway Reconnect → health `edaConnected:true` 확인.
