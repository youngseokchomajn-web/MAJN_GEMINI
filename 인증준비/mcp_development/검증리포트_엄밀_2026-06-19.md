## 0. 검증 방법론 (왜 이전 보고와 결론이 다른가)

- 이전 감사(`schematic_audit_report.md`, `오동규 수정.md`)는 **에디터 라벨 개수 ↔ 스펙(`mcp_design_flow.json`) 핀 개수**만 비교했고, DRC는 **기하학적 규칙(클리어런스/선폭)** 만 본다.
- 본 검증은 **실제 Gerber에 박힌 패드별 네트(FlyingProbeTesting.json)** 를 **TI/ST/MPS 데이터시트의 핀 기능**과 직접 대조했다. → 라벨이 "있어도" **엉뚱한 핀**에 붙은 것을 잡아낸다.

## 1. ⛔ CRITICAL — 동작 자체가 불가능한 결함

### C1. ESP32(U1)가 거의 모든 신호에서 분리되어 있음
실측 넷리스트 기준, ESP32 39핀 중 **외부와 연결된 핀은 6개뿐**:

| 연결된 것 | 핀 |
|---|---|
| GND | U1_1 |
| 3.3V | U1_2 |
| SPI SCLK / MISO / MOSI | U1_30 / U1_31 / U1_37 (→ 센서 U5) |
| 센서 INT1 | U1_6 (→ U5_4) |

**나머지 33핀은 전부 단일핀 자동네트(NET_22 ~ NET_63) = 미연결.** 즉 아래가 **ESP32 핀에 연결되지 않음**:
- **EN(리셋)** — `ESP_EN` 네트에 U1 핀 없음(U1_3=NET_22 부유)
- **IO0(부트)** — `ESP_IO0`에 U1 핀 없음
- **UART TXD/RXD** — `ESP_RXD`={UART_HDR_5}만, `ESP_TXD`={UART_HDR_4}만 → **펌웨어 다운로드/디버그 불가**
- **I2S BCLK/LRCLK/DIN** — 세 네트 모두 U4(앰프) 핀만 있고 U1 핀 없음 → **오디오 데이터 경로 없음**
- **I2C SDA/SCL** — 네트 자체가 존재하지 않음 → **앰프 제어 불가**
- **BOOST_EN(GPIO4)** — 네트 자체가 없음 → **안전 차단 제어 불가(아래 C5)**
- **SPI CS(GPIO5)** — `SPI_CS`={U5_5}만, U1 핀 없음 → 센서 선택 불가

> ESP32 모듈의 방열/접지 패드(U1_39)도 GND가 아니라 9개의 부유 네트(NET_55~63)로 쪼개져 있음 → 모듈 메인 그라운드 미연결(H2).

### C2. 12V 부스트 컨버터 U3(MP3426)가 2핀짜리로 배치됨
- C162810 = MPS **MP3426, QFN‑14**(6A/35V 부스트)가 맞음. 그런데 **에디터/Gerber에 배치된 U3는 패드가 2개뿐**: `U3_1=NET_66(부유)`, `U3_2=GND`.
- 결과: VIN(5V)·SW(인덕터)·FB·EN이 **U3에 연결 불가**. `VBUS_5V`·`BOOST_SW`·`BOOST_FB`에 U3 핀이 하나도 없음.
- ⇒ **12V(PVDD)는 영원히 생성되지 않음.** 앰프(U4)·액추에이터(TT25) 구동계 **전체 사망.**
- `오동규 수정.md` §"U3 핀 이름 이슈"가 이미 동일 현상을 보고했으나 **임시 처리(2핀에 BOOST_SW/EN 배치)** 로 종결됨 → 실제로는 미해결 치명 결함.

### C3. 가속도 센서 U5(LSM6DSOX) 핀 교차배선 — 센서 사망
ST 데이터시트 LGA‑14: **pin5=VDDIO, pin9=VDD, pin12=CS**, pin1=SDO, pin13=SPC, pin14=SDI, pin4=INT1.
실측 결과:

| U5 핀 | 데이터시트 기능 | 실제 연결된 네트 | 판정 |
|---|---|---|---|
| 1 | SDO (MISO) | SPI_MISO | ✅ |
| 13 | SPC (SCLK) | SPI_SCLK | ✅ |
| 14 | SDI (MOSI) | SPI_MOSI | ✅ |
| 4 | INT1 | NET_25(→U1_6) | ✅ |
| **5** | **VDDIO(전원)** | **SPI_CS** | ⛔ CS 신호를 전원핀에 인가 |
| **12** | **CS** | **VCC_3V3** | ⛔ 3.3V를 CS핀에 고정(영구 deselect) |
| **9** | **VDD(주전원)** | (NET_82, 부유) | ⛔ **센서 주전원 미연결** |

⇒ VDDIO/VDD 미공급 + CS가 MCU에 연결조차 안 됨(`SPI_CS`에 U1 핀 없음). **센서 동작 불가 → 폐루프(closed‑loop) 진동 제어라는 핵심 설계 목표 구현 불가.** 전원핀에 로직 신호를 인가하므로 **소자 손상 위험**도 있음.

### C4. 오디오 앰프 U4(TAS5805M) 인터페이스 오결선
TI 데이터시트 PWP‑28: **LRCLK=6, SCLK(BCLK)=7, SDIN=8, SDOUT=9, SDA=10, SCL=11, PDN=12, PVDD=15, PowerPAD=GND**.
실측 결과:

| U4 핀 | 데이터시트 | 실제 네트 | 판정 |
|---|---|---|---|
| 7 | SCLK(BCLK) | I2S_BCLK | ✅ (우연히 일치) |
| **8** | **SDIN** | **I2S_LRCLK** | ⛔ LRCLK를 SDIN핀에 |
| **9** | **SDOUT(출력)** | **I2S_DIN** | ⛔ 데이터입력을 출력핀에 |
| **10 / 11** | **SDA / SCL** | NET_72 / NET_73(부유) | ⛔ 실제 I2C핀 미연결 |
| 12 | PDN | AMP_PDN(U1핀 없음) | ⛔ MCU가 PDN 구동 안 함 |
| **29** | **PowerPAD = GND** | **PVDD_12V** | ⛔ 방열패드에 12V 인가 |
| 3 | ADR/FAULT(설정핀) | GND | ⚠ 직결(주소설정 부작용) |

⇒ **I2C 제어 부재 + I2S 데이터핀 오결선 + 방열패드 12V 단락 위험.** 앰프 **설정·구동 불가.**

### C5. 안전 비상 차단 회로가 하드웨어에 없음
설계 목표/펌웨어: 충격 감지 ISR이 `GPIO4 → MP3426 EN`을 Low로 떨궈 12V 즉시 차단(영유아 안전 핵심).
실측: **`BOOST_EN` 네트 자체가 존재하지 않고**, U3에는 EN 패드도 없음. ⇒ **헤드라인 안전 기능이 물리적으로 미구현.** (KC 어린이제품 안전 관점에서 중대.)

### C6. 펌웨어 업로드/디버그 불가
`UART_HDR`(6핀)는 GND/3V3까지는 연결되나 **TXD/RXD/EN/IO0이 ESP32 핀에 도달하지 않음**(C1). ⇒ 보드를 만들어도 **플래시·리셋 불가.**

## 2. 🔶 HIGH — 신뢰성/제조 결함

- **H1.** ESP32 EN 풀업(R5) 및 RC(C17)가 ESP32 EN핀에 연결 안 됨(`ESP_EN`에 U1 없음) → **부팅 불가/불안정.**
- **H2.** ESP32 방열 그라운드 패드(U1_39) 미접지(NET_55~63) → 방열·접지 리턴 불량.
- **H3.** I2C 풀업 저항 자체가 BOM/네트에 없음(연결을 고치더라도 SDA/SCL 풀업 필요).
- **H4.** `USB_CC1` 네트에 USB‑C의 CC1 패드가 빠짐(`={R3_1}`만) → CC 검출 한쪽만 동작(UFP 인식 불안정).
- **H5.** Gerber/PCB PDF(06‑18)·BOM이 회로 수정과 비동기. PCB PDF에는 아직 **UART 2핀(C124375)** 과 스펙에 없는 **R8/R9**, 다른 패시브 LCSC ID가 보임 → 출력본 형상 관리 붕괴.

---

## 3. 🟡 MEDIUM — 펌웨어/부품 선정

- **M1.** 펌웨어가 AMP_PDN(GPIO15)을 전혀 제어하지 않음(스펙엔 배정). GPIO15는 strapping 핀 → 부팅 영향 가능.
- **M2.** `pinMode(GPIO34, INPUT_PULLDOWN)` — GPIO34~39는 내부 풀다운이 **없음**(무효). INT 네트에 외부 풀다운도 없음.
- **M3.** 펌웨어 핀맵(CS=GPIO5, I2C=GPIO21/27)과 하드웨어가 불일치(해당 연결 자체가 없음).
- **M4.** D1=SMAJ5.0A: 5V 레일에 standoff 5.0V는 마진이 빠듯(통상 허용이나 누설 가능).

## 4. 설계 의도(부품 선정) 수준 평가 — 배선과 별개

연결만 바로잡는다는 전제에서, **부품 선정 자체는 대체로 타당**:
- TAS5805M(필터리스 Class‑D, I2S) + TT25 보이스코일: 정현파 30~65Hz 구동에 적합.
- LSM6DSOX 가속도 더블 적분 → 변위(10~12μm): **절대 변위 정밀도는 낙관적**. 펌웨어는 leaky integrator라 **상대 진폭 조절**에 가깝고 교정된 절대 10μm 보장은 어려움(설계 철학상 한계, 버그는 아님).
- MP3426 FB 분압 R1=150k/R2=16k: Vref≈1.2V 가정 시 ≈12.4V로 목표 근사(부스트가 살아있을 때만 의미).
- 85dB 제한: TAS5805M AGL + 펌웨어 볼륨락 = **소프트웨어 잠금만**. 인증상 하드웨어 리미트 병행 권장.

## 5. 왜 "PASS"로 잘못 보고되었나

1. **DRC = 기하 검사만.** 핀 기능·전기 연결의 정합성은 검사 대상이 아님.
2. **넷 감사 = 라벨 개수 비교.** 라벨이 **틀린 핀**에 붙어도 "개수 일치"로 통과.
3. **구동 스펙(`mcp_design_flow.json`)의 핀 번호가 데이터시트와 불일치.** U4의 I2C/I2S, U5의 CS/전원이 처음부터 잘못된 핀 번호로 정의됨. 게다가 **U5.5가 VCC_3V3와 SPI_CS에 이중 배정**되어 있었음(스펙 자체 모순).
4. 파이프라인이 회로도(schematic) 없이 **핀 번호 직접 배선**이라, 번호 오류가 그대로 동박에 박힘. ESP32 측 라벨은 대부분 누락되어 GPIO들이 부유 네트로 남음.

## 6. 권고 (우선순위)

1. **설계 방식 전환:** 핀‑번호 직접배선 대신 **정식 Schematic을 그리고 LCSC 심볼의 핀 이름 기준으로 배선** → ERC(전기규칙검사) 수행. 현 파이프라인은 핀 기능 검증 단계가 구조적으로 빠져 있음.
2. **U3(MP3426)**: 올바른 QFN‑14 심볼/풋프린트로 교체, VIN/SW/FB/EN/GND(+EP) 전부 결선.
3. **U4(TAS5805M)**: SDA=10, SCL=11, SDIN=8, SCLK=7, LRCLK=6, PDN=12, PowerPAD=GND로 정정. I2C 풀업(예: 2.2k~4.7k) 추가.
4. **U5(LSM6DSOX)**: VDD(9)·VDDIO(5)=3V3, CS(12)=GPIO5로 정정. INT1 유지.
5. **ESP32 핵심 결선 복구:** EN(풀업+RC), IO0(풀업), UART TXD/RXD, I2S(26/25/22), I2C(21/27), BOOST_EN(4), SPI_CS(5), 그리고 **EP 패드 GND**.
6. **안전 차단(BOOST_EN) 결선**은 인증 항목 직결 — 반드시 복구.
7. Gerber/BOM **재출력 및 형상 관리**(현 출력본 폐기).
8. 정정 후 **본 리포트의 §1~2 항목을 체크리스트로 재검증**(실측 넷리스트 ↔ 데이터시트).
