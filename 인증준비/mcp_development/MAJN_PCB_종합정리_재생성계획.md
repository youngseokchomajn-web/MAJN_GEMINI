# PART 1. 제품 컨텍스트 & 작동 의도

## 1.1 제품 정의
**마중 스마트 배시넷** — 영유아용 **자동 진정(soothing) 배시넷**. KC 인증 대상(영유아 제품).
핵심 기능:
- **진동 진정**: 30–65Hz 사인파 진동(보이스코일 액추에이터)으로 아기 달램. IMU 가속도 피드백 기반 **폐루프 진폭 제어**.
- **안전 정지(핵심 KC 기능)**: 충격/낙하 감지(IMU INT1) 시 **BOOST_EN(GPIO4)으로 12V 비상 차단**.
- **오디오 알림**: 스피커 출력(부모 알림), 펌웨어 85dB SPL 상한.
- **무선 제어**: ESP32 WiFi/BT + 앱.

## 1.2 전원 아키텍처
```
USB-C 5V ─ D1(TVS) ─ C3(입력필터) ─ VBUS_5V ┬─ U2(LDO SGM2036) ─ VCC_3V3(3.3V) ─ U1·U4(DVDD)·U5·로직
                                            └─ U3(MP3426 부스트) ─[L1·D3]─ PVDD_12V(12V) ─ U4(앰프)·진동액추에이터·C6/C7
                                               (EN=GPIO4 ← 안전 비상차단)
```

## 1.3 핵심 부품 (BOM 역할)
| 지정자 | 부품 | LCSC | 역할 |
|---|---|---|---|
| U1 | ESP32-WROOM-32E | C701342 | 메인 MCU (I2S/I2C/SPI/UART/GPIO) |
| U2 | SGM2036-3.3 LDO | C81114 | 5V→3.3V 로직 전원 |
| U3 | MP3426 부스트(QFN-14+EP) | C162810 | 5V→12V (6A/35V급), ~540kHz |
| U4 | TAS5805M Class-D 앰프(HTSSOP-28+EP) | C478472 | I2S 입력, 진동액추에이터+스피커 구동 |
| U5 | LSM6DSOX IMU(LGA-14) | C481766 | 6축, SPI, 낙하감지(INT1)+진동 피드백 |
| L1 | 파워 인덕터 | C168239 | 부스트 스위칭 (4.7µH, 데이터시트 권장 6.8µH) |
| D3 | MBR140 쇼트키 | C186407 | 부스트 프리휠링 |
| J1/J2 | 1×2 커넥터 | C124372 | AMP_OUT_A±/B± (액추에이터/스피커) |
| USB_C | Type-C 16P | C165948 | 전원입력 + CC1/CC2 |
| UART_HDR | 1×6 헤더 | C124380 | 3V3·EN·IO0·TXD·RXD·GND (펌웨어/디버그) |

## 1.4 전류·전원폭 설계의도 📄
- 입력 VBUS_5V ~3A(부스트+앰프+MCU), PVDD_12V 피크 ~2A(진동액추에이터+앰프), VCC_3V3 ~0.4A.
- **설계 목표 트레이스 폭(런북 S5-4)**: VBUS_5V **1.2mm**, PVDD_12V **1.0mm**, BOOST_SW **0.8mm**, VCC_3V3/신호 **0.25mm(10mil)**.
- ⚠️ 진동 액추에이터가 12V 주부하 → **전원폭이 실제로 중요**(단순 저출력 오디오가 아님).
- 보드 80×60mm, ESP32 안테나 keepout, **U3-L1-D3 스위칭 루프 ≤2mm 최소화**.

# PART 2. 회로도/넷리스트 (정정 완료 — 새 PCB가 물려받는 설계)

회로도(Schematic1)는 원 설계자(오동규) 오류를 S1~S7로 전면 정정 완료. **현재 PCB3·PCB3_1 둘 다 이 정정 넷리스트와 일치(✅이번 세션 확인: 38넷, 두 보드 넷 구성 0개 차이).** 새 PCB도 동일 회로도에서 생성하므로 정정이 자동 반영됨.

## 2.1 주요 정정 (원오류 → 수정) 📄
- **U4(앰프) — 가장 중대**: EP(pin29) **12V→GND**(열패드, 단락/열폭주 위험). PVDD 15·16·27·28 **4핀 모두→12V**(원래 15만). DVDD(2)→3.3V+디커플, DGND(1,5)/PGND(19,24)→GND. I2C **SDA=10·SCL=11**(원래 5·6 오결선). I2S **LRCLK=6·DIN=8**(원래 8·9 오결선), BCLK=7. PDN=12. AVDD(13)·VR_DIG(4) 디커플만.
- **U3(부스트)**: 풋프린트 **2패드→QFN-14+EP(15패드)**. VIN(3)/SW(4,5,6)/FB(13)/EN(2)/COMP(1)/FSET(14)/VDD(7)/EP=GND 결선. FB 분압 R1=150k/R2=16k(≈12.7V), COMP R10=24.9k+C22=4.7nF, FSET R9=84.5k.
- **U5(IMU)**: VDDIO(5)·VDD(8)→3.3V(원래 로직신호/오핀), CS(12)→SPI_CS(원래 3.3V 고정), INT2(9)→NC.
- **U1(ESP32)**: 부동핀(EN/IO0/I2S/I2C/BOOST_EN/SPI_CS/EP) 전부 결선, EP(39)→GND.
- **USB_C**: CC1(A5)→R3(5.1k), CC2(B5)→R4(5.1k) 풀다운. D±/SBU 미사용 NC.
- **추가 부품**: I2C 풀업 R7/R8(2.2k), 각종 디커플 캡.

# PART 3. PCB 제작 중 발생한 모든 오류 (PCB1~PCB3_1)

## 3.0 보드 계보
- **PCB1**: 빈 템플릿, 폐기.
- **PCB2**: 원오류 넷리스트로 배선 → C1~C6 전기결함(MCU 33핀 부동, 부스트 2패드, IMU 전원오결선, 앰프 I2C/I2S/EP 오류) + **동박 손상** → 폐기.
- **PCB3**: 정정 넷리스트로 생성. ✅**이번 세션 직접 확인: 592트랙/77비아, 완전배선, UI DRC "All (0)", EP=GND, 열비아 12개 GND, 회로도 일치.** 📄옛 문서엔 "미배선"이라 기록됐으나 그 후 배선 완료된 상태로 확인됨.
- **PCB3_1**: PCB3와 **넷리스트 동일**한 별도 레이아웃(재배선 시도). ✅**현재 DRC 50개**(미완성/망가짐). ⚠️왜 만들었는지는 문서/전사에 명확치 않음 — 넷리스트가 같으므로 "전기 문제"가 아니라 "레이아웃 재시도"였고 미완성으로 남음. (사용자 기억: "PCB3 문제로 PCB3_1 생성" — 단 데이터상 PCB3가 더 깨끗함. 이 모순은 재검증 필요 ⚠️)

## 3.1 DRC 오류 수 변천 (전사 기준) 📄
| 시점 | 보드 | 총 | 클리어런스 | 미연결 | 같은풋(열비아) |
|---|---|---|---|---|---|
| 오토라우트 직후 | PCB3 | 97 | 48 | 37 | 12 |
| GND 동박 시도 후 | PCB3 | 116 | 42 | 37 | – |
| 정정 후 현재 | **PCB3_1** | **50** | 24 | 14 | 12 |
| PCB3 현재 | **PCB3** | **0** ✅ | 0 | 0 | 0 |

## 3.2 PCB3_1 현재 50개 오류 상세 (✅직접 확인, 3개 군집)
**A. U4 열패드 군집 — 32개**: EP 밑 비아 12개가 빈-네트(GND 아님).
- 같은풋프린트 12 (EP↔비아 0mil)
- Track↔Via 클리어런스 13 (GND 스티치 트랙 e3091~e3101 + I2S_DIN 바텀 e2966이 비아와 0~5mil)
- Hole↔Track 7 (GND 트랙이 비아 드릴홀 가로지름)

**B. USB-C 충돌 군집 — 8개**: R3/R4가 USB-C 장착홀에 0mil 겹침.
- 클리어런스 4 (R3_2↔USB_C_2, R4_1↔USB_C_3 — SMD↔TH + Hole↔SMD)
- 미연결 4 (GND R3_2, USB_CC2 R4_1 + 상대단 e2993/USB_C_B5 — 겹쳐서 배선 불가)

**C. 미세핀 신호 미배선 — 10개**: U4 0.65mm 핀으로 가는 마지막 홉 미완.
- AMP_I2C_SCL(R8_1·U4_11), AMP_I2C_SDA(e418·U4_10), BOOST_FB(R2_1·U3_13), VR_DIG(C20_1·U4_4), I2S_LRCLK(U1_10·U4_6)

## 3.3 초기 배치 쇼트 (오토라우트 단계) 📄
디커플 캡/저항(C7·C8·C9·C21·C22·R6·R9·R11·R4)이 IC 핀에 0mil 겹침 → modify로 떼어내 해결(이후 단계).

## 3.4 열비아 quirk ✅
EP 밑 12비아: 빈-네트면 같은풋프린트 무오류처럼 보이나, **GND로 지정+동박재생성하면 같은풋12 + Copper Region↔Via/Hole 53개 폭발**(동박이 밀집 비아 배열을 6mil로 못 채움). PCB3_1에선 미해결. **단 PCB3는 동일 EP+12 GND비아인데 DRC 0** → PCB3는 이 문제를 푼 레이아웃(비아 배치/동박 처리가 깨끗). ⇒ **새 PCB는 PCB3 방식(GND 비아 + 깨끗한 동박)을 따르면 됨.**

## 3.5 전원폭 미흡 ✅📄
PCB3·PCB3_1 둘 다 전원 트레이스 ~10mil (DRC엔 안 잡힘). 설계의도는 VBUS 1.2/PVDD 1.0/BOOST_SW 0.8mm. 과거 폭 확대 시도 → **클리어런스 폭발**(공간 부족)로 되돌림. **두더지잡기의 핵심 원인**.

## 3.6 GND 동박 전략 문제 ✅
GND 평면이 있는데도 GND 트랙 168개가 따로 깔림(오토라우트 잔재) → Top층 포화 → Track↔Via 클리어런스 + 전원 못 키움. **GND는 평면+스티칭으로 일원화해야 함.**

## 3.7 동박 클리어런스 규칙 불일치 ✅
pour 클리어런스 2mil인데 설계규칙 6mil → 동박이 6mil 미만으로 채워져 Copper Region 오류 유발. **pour 클리어런스를 6mil로 맞춰야 함.**

## 3.8 브릿지/도구 문제 (실행상 — 설계와 무관하나 작업 차단) ✅
- **창 바인딩 이동**: 재시작/리로드 시 브릿지가 빈 호스트창에 붙음 → `location.reload()`로 에디터창 폴백 + windowId 명시 지정으로 해결.
- **DRC 120초 타임아웃 + degrade**: **브릿지 동박재생성 rpcCall이 방아쇠** → 이후 무거운 작업(DRC/clearRouting/rebuild) 전부 멈춤. fresh 렌더러는 DRC 1초.
- **저장/클라우드 동기 꼬임**: 저장 직후 리로드하면 변경이 되돌려짐.
- **"DRC 0 거짓" 이력**: 과거 브릿지가 null 반환 → 거짓 0. (이번엔 UI 패널 "All (0)"로 교차검증해 PCB3는 진짜 0.)

# PART 4. 오류를 없애는 "새 PCB 생성" 계획

> **원칙: 규칙 먼저 → 좋은 배치 → 전원 우선 배선 → 신호 → 검증.** 모든 단계는 PART 3의 특정 오류를 *구조적으로* 차단하도록 설계됨.

## STEP 0. (권장 선행) PCB3 정밀 재검증 — 헛수고 방지
PCB3가 이미 동일 회로 + DRC 0이므로, **새로 만들기 전에 PCB3가 정말 쓸 수 있는지 엄밀 검증**:
- UI DRC 0 재확인(✅완료) + 넷리스트=회로도 재확인(✅완료) + 전원폭 확인(⚠️10mil).
- **EP 접지·열비아·동박 연속성·드릴/외형 DFM** 최종 점검.
- 결론 분기: PCB3가 건전하면 → **"새 PCB" = PCB3 복제 후 전원폭만 보강**(최소 작업). PCB3에 실제 결함이 있으면 → 아래 풀 빌드.
- *사용자가 PCB3를 불신하므로, 결함을 못 찾아도 풀 빌드로 가도 됨. 단 이 검증으로 "무엇을 안 틀리게 할지" 기준이 명확해짐.*

## STEP 1. 규칙 설정 (UI: Design>Net Class Manager / PCB Design Rule) — PART3.5/3.7 차단
- 클리어런스 6mil, 홀↔동박 6.9mil.
- **pour 클리어런스 = 6mil** (현 2mil → Copper Region 오류 차단).
- **같은-넷 via-in-pad 허용**(열비아용) 또는 PCB3식 GND 열비아 처리.
- **넷클래스 폭**: VBUS_5V 1.2mm · PVDD_12V 1.0mm · BOOST_SW 0.8mm · AMP_OUT_A±/B± 0.5mm · VCC_3V3/신호 0.25mm · GND=평면.

## STEP 2. 새 PCB 생성 (지울 것 없는 깨끗한 출발)
- 방법 ⓐ(권장): **PCB3 복제** → 깨끗한 DRC-0 배치/배선 그대로 + STEP1 규칙 적용 + STEP5 전원폭 보강. (최소 위험)
- 방법 ⓑ: 새 빈 PCB + 회로도 Import → 부품 더미에서 재배치(풀 빌드, 최대 노력).

## STEP 3. 배치 (풀 빌드 시) — PART3.2-B/C, 3.3 차단
- 기능 그룹: [USB-C·CC저항·LDO] → [부스트 U3·L1·D3·캡 **루프 최소**] → [앰프 U4] → [J1/J2].
- **U1↔U4 인접/마주봄**(I2C·I2S 6넷 단축 → 미배선 차단), U5는 U1 옆(SPI).
- **R3/R4를 USB-C 장착홀에서 이격**(코트야드 준수 → 충돌 차단).
- 디커플 캡은 IC 전원핀 옆이되 **0mil 겹침 금지**(쇼트 차단). ESP32 안테나 엣지+keepout.

## STEP 4. GND 평면화 — PART3.6 차단
- GND = **Inner1 솔리드 평면 + 스티칭 비아**. GND 시그널 트랙 금지(168개 잔재 방지).
- U4/U3/U1 EP는 인접 GND 비아로 평면 직결(**PCB3식 깨끗한 열비아**).

## STEP 5. 배선 — 전원 우선 — PART3.5 차단
- **전원 동맥 먼저**(STEP1 폭으로): VBUS→부스트→PVDD→앰프, BOOST_SW 최단.
- 그 다음 신호(Inner2). 미세핀(U4)은 핀 수직 이스케이프 → 비아 → Inner2.
- **사후 폭 확대 금지**(처음부터 규칙 폭으로 깔기 → 클리어런스 폭발 방지).

## STEP 6. 검증 & 출력 — PART3.8 차단
- 무거운 작업(배선삭제/오토라우트/동박재생성/DRC)은 **UI로 실행**(브릿지 rpcCall 금지 → degrade 방지).
- **UI DRC로 0 확인**(브릿지 단독 신뢰 금지 → 거짓0 방지): 클리어런스/미연결/같은풋 모두 0.
- 넷리스트=회로도 재대조, 전원폭/EP접지 확인. 동박재생성 후 저장→**클라우드 동기 대기**→Gerber 재출력(기존 zip 폐기).

## STEP 7. 도구 운영 수칙 (작업 안정성)
- 브릿지: 읽기/부품이동(modify)만. 동박재생성·대량삭제는 UI.
- windowId 고정(끊기면 `location.reload`로 에디터 폴백 후 재바인딩).
- 저장 후 리로드 금물(동기 완료까지 대기). 백업 JSON 상시.

## 핵심 결론
1. **회로도/넷리스트는 정정 완료** — 새 PCB는 정상 회로를 물려받음.
2. **PCB3는 이미 DRC-0 완성 보드로 보임**(UI 확인) — 유일 미흡은 전원폭. ⇒ **가장 빠른 길은 STEP0 검증 후 PCB3 기반 + 전원폭 보강**.
3. 풀 빌드를 하더라도 **규칙-먼저(STEP1) + GND평면(STEP4) + 전원우선(STEP5) + UI검증(STEP6)**이면 PART3의 50개 오류가 *생기지 않음*.
4. **두더지잡기 원인은 "규칙 없이 + 사후 전원폭 확대 + 브릿지 동박재생성"** — 이 셋을 STEP1/5/7로 제거.
